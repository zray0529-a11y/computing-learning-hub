## 机制一：坐标数值必须带着解释使用

`(100, 200)` 可能是局部模型中的毫米坐标，也可能是某个平面坐标系统中的米坐标。
仅有两个数字，不能判断点在地球上的位置，也不能知道哪一个轴朝向何处。
坐标参考系统（CRS）就是解释坐标所用的基准、轴及单位等约定；投影坐标系统还说明怎样把地球表面映射到平面。
拿到一份数据时，先把下面的问题回答完整。

| 必查信息 | 为什么会影响结果 |
| --- | --- |
| 坐标参考系统或局部基准 | 决定原点、轴向及数值与空间的对应关系 |
| 轴顺序 | 第一列不一定就是想当然的经度或东向坐标 |
| 单位 | 同一个数值可对应不同的实际长度 |
| 水平与竖向解释 | 平面位置一致，不代表高程基准一致 |
| 数据来源与变换记录 | 决定怎样核对结果和追踪偏差 |

PROJ 是处理坐标参考系统与变换的软件库。其官方说明，坐标轴顺序会遵循参考系统的定义，但不同软件接口也可能有自己的约定。[1]
因此，要同时检查源数据说明和调用接口，而不能一律假设“经度在前”。

## 机制二：贴标签与变换坐标是两种操作

一张图漏写了坐标基准，补齐图签是在说明“原来这些数是什么含义”；若要交给使用另一套坐标基准的人，则要按正确变换重算位置数字。
前一种操作不移动点；后一种操作依据源、目标系统计算同一位置的新表示。
这个类比的边界是：参考系统不只是图纸比例尺，还可能涉及地球基准、轴、单位和投影，不能把所有转换理解成乘一个缩放系数。

PostGIS 是 PostgreSQL 数据库的空间数据扩展；SRID 是空间参考系统的标识编号，用于查到坐标的解释。[2][3]

| 操作 | 实际改变什么 | 适用前提 |
| --- | --- | --- |
| `ST_SetSRID` | 设置或修正参考系统的元数据，坐标数字不变 | 已核实原数字使用哪个参考系统，才给它填上正确编号 |
| `ST_Transform` | 依据源、目标参考系统计算新坐标 | 源定义正确，且选用的转换适用于该数据和范围 |

把原数据随手贴成目标 SRID，不会完成转换，反而可能让后续运算误解原坐标。[2][3]

局部模型接入场地时，还可能需要单位换算、平移和旋转。
这些操作的顺序必须明确：先平移再旋转，与先旋转再平移一般不同。
仅在屏幕上拖到“看起来重合”，不会自动补齐可复现的变换记录。

本篇实验演示单位换算和二维刚体变换；它不是两个地理参考系统之间的投影转换。
真实地理转换还应使用适合源、目标及适用范围的工具和变换定义。[3]

## 机制三：坐标对齐后，才能判断 P 和 Q 在哪里

图中蓝色模型的目标坐标范围是 `97 ≤ x ≤ 100`、`200 ≤ y ≤ 204`，而虚线**查询矩形**是 `98 ≤ x ≤ 102`、`201 ≤ y ≤ 203`，单位都为米。
两者是不同的几何对象：蓝色轮廓表达模型，虚线框表达本次要查的区域，不能把模型外框当作查询边界。

可以设想查询“哪些虚构测点落在这个区域内”。P 的坐标 `(99, 202)` 同时满足两个方向的严格不等式，所以在内部；Q 的坐标 `(103, 203.5)` 超出范围，所以在外部。
再补一个图中未画出的边界测试点 B：`(100, 201)`。它恰好位于查询矩形下边，是否计入必须由任务规则说明。

| 点 | 与查询矩形的关系 | 只算内部 | 内部及边界都算 |
| --- | --- | --- | --- |
| P `(99, 202)` | 内部 | 是 | 是 |
| Q `(103, 203.5)` | 外部 | 否 | 否 |
| B `(100, 201)` | 边界 | 否 | 是 |

对应到 PostGIS，**对“多边形与单个点”这一情形**，`ST_Contains` 不包含仅落在边界上的点，`ST_Covers` 包含内部和边界上的点。[5][6]
不能把这个简化直接当作任意两种几何对象的完整定义；本篇代码只用矩形的范围比较实现这三种结果，不调用 PostGIS。
真实边界若存在孔洞、自交或测量误差，还要选择相应的几何检查与误差规则；叠图看起来相近不能替代这些条件。

## 机制四：面积的单位来自计算方法

在平面坐标中，用同一单位表示边长，得到的面积就采用该单位的平方。
因此，从毫米变成米时，长度缩小 1000 倍，面积数值缩小 1000000 倍。
这可以直接从矩形的“长乘宽”推导，不需要任何 GIS 软件。

PostGIS 对 `geometry`（平面几何对象）使用二维平面面积，单位由空间参考决定；
对 `geography`（地球表面地理对象）默认在椭球上计算面积，结果为平方米。[4]
把经纬度数字直接套入平面公式，并不能自动得到平方米。
选择测量方法之前，应先问自己需要的是局部平面量还是地球表面的量。

### 面积公式为什么这样写

矩形可以直接长乘宽，顶点更多的简单多边形则可以用**鞋带公式**：按边界顺序走一圈，把每对相邻顶点与原点组成的三角形面积带着正负号相加。
相邻点 `(x1, y1)`、`(x2, y2)` 对应的有向平行四边形面积是 `x1*y2 - x2*y1`，三角形是它的一半；沿闭合边界相加时，多边形之外的部分会抵消，最后取绝对值得到面积。
“鞋带”这个名称来自相邻坐标交叉相乘的样子；代码还必须把最后一个顶点连回第一个。

用图中的米制矩形 `(0,0)、(4,0)、(4,3)、(0,3)` 手算，四条边的乘积差分别是 `0、12、12、0`，所以面积为 `|0+12+12+0|/2 = 12` 平方米。
倒着走一圈会改变有向和的符号，绝对值后的面积不变。这个推导针对平面上的简单无孔多边形，不会自动处理自交或孔洞。

## 最小实验：检查变换，再查询区域内的点

一个 4000 × 3000 毫米的教学矩形，先换算成米。
再将其逆时针旋转 90°，最后平移到局部目标原点 `(100, 200)` 米。
预期面积和对角线长度在刚体变换前后保持一致；再用同一目标坐标检查 P、Q 和文字补充的 B。

```python
from math import hypot

raw_mm = [(0, 0), (4000, 0), (4000, 3000), (0, 3000)]

def area(points):
    # 最后一对连接末点与首点；每个乘积差是两倍有向三角形面积。
    pairs = zip(points, points[1:] + points[:1])
    return abs(sum(x1 * y2 - x2 * y1 for (x1, y1), (x2, y2) in pairs)) / 2

def to_world(point):
    x, y = point
    # 先旋转为 (-y, x)，再加平移量 (100, 200)，输入单位已经是米。
    return (100 - y, 200 + x)

def relation_to_rectangle(point, bounds):
    x, y = point
    xmin, ymin, xmax, ymax = bounds
    if not (xmin <= x <= xmax and ymin <= y <= ymax):
        return "outside"
    if xmin < x < xmax and ymin < y < ymax:
        return "inside"
    return "boundary"

local_m = [(x / 1000, y / 1000) for x, y in raw_mm]
world_m = [to_world(point) for point in local_m]
diagonal = hypot(world_m[2][0] - world_m[0][0], world_m[2][1] - world_m[0][1])
assert area(local_m) == area(world_m)
assert diagonal == 5.0
print(f"raw_area_mm2={area(raw_mm):.0f}")
print(f"local_area_m2={area(local_m):.2f}")
print(f"world_vertices={world_m}")
print(f"world_area_m2={area(world_m):.2f}")
print(f"diagonal_m={diagonal:.2f}")
query_bounds = (98, 201, 102, 203)
query_points = {"P": (99, 202), "Q": (103, 203.5), "B": (100, 201)}
for name, point in query_points.items():
    relation = relation_to_rectangle(point, query_bounds)
    # 此处只比较矩形与单个点：contains 排除边界，covers 包含边界。
    contains = relation == "inside"
    covers = relation != "outside"
    print(f"{name}: relation={relation} contains={contains} covers={covers}")
```

确切预期输出：

```text
raw_area_mm2=12000000
local_area_m2=12.00
world_vertices=[(100.0, 200.0), (100.0, 204.0), (97.0, 204.0), (97.0, 200.0)]
world_area_m2=12.00
diagonal_m=5.00
P: relation=inside contains=True covers=True
Q: relation=outside contains=False covers=False
B: relation=boundary contains=False covers=True
```

如果只把原始数据的单位标签改成米，而不除以 1000，面积数值仍是 12000000。
标签与数值就会矛盾，这与“只指定参考系统不会重新计算坐标”的区别相呼应。
面积公式在本实验中用于按边界顺序给出的简单无孔多边形；不是完整的几何有效性检查器。
点查询函数只适用于边与坐标轴平行的非退化矩形，且预先约定 `xmin < xmax`、`ymin < ymax`；不能拿任意多边形的外接矩形替代它自己的内部。
实验使用能精确表示的简单数值；一般浮点运算的结果比较应采用说明过的误差容许范围。

## 把模型与场地叠加时怎样核对

用已知的多个控制点核对方向、距离和位置，避免只比较一个看起来正确的角点。
另行检查高程解释、单位及变换顺序，并保留源坐标到目标坐标的参数或转换定义。
若几何用于面积或相交查询，还应检查边界是否自交、是否缺边以及孔洞表达是否正确。
这些是数据检查步骤；具体精度要求应来自任务依据，本文没有给出统一容差。

2. 毫米坐标只除以 1000，面积数值为何要变化 1000000 倍？
3. 两份数据的平面位置重合，是否足以证明模型高程也正确？
4. 图中 P 在查询区域内，能否因此认为模型轮廓就是查询区域？B 又应如何处理？

2. 面积由两个长度相乘，两个方向各缩小 1000 倍，所以面积数值缩小 1000000 倍。
