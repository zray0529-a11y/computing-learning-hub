# 建筑专业分类：把计算机基础用在空间问题上

[返回仓库首页](../README.md) · [计算机章节目录](../docs/chapters/index.md)

这里补充四类建筑专业入口，面向建筑学生和希望补齐计算机基础的从业者。
可以先从熟悉的建筑问题出发，再回到对应的计算机章节理解机制。
全部房间、构件、测点和数值都是虚构的教学示意。

## 学习目标

- 把“软件按钮怎么点”进一步转化为“数据怎样表示、计算和验证”。
- 能说明一次建筑计算的输入、输出、单位、假设和失败条件。
- 能复算一个小例子，并解释结果为什么成立、在哪些条件下不成立。

## 建议的阅读顺序

### 从模型与清单开始

先读 BIM 篇，用对象标识连接构件和楼层，再读数据库章节。
完成后，检查自己能否解释“同名对象”和“同一对象”有什么区别。

### 从形体与规则开始

先读参数化篇，把一个形体操作写成明确的输入和函数，再读算法章节。
完成后，检查自己能否区分候选生成、约束过滤和结果排序。

### 从场地与位置开始

先读 GIS 篇，手算一次单位换算和刚体变换，再读空间系统章节。
完成后，检查自己能否解释给坐标换标签为什么不会移动点。

### 从运维与观测开始

先读数字孪生篇，重放一组乱序观测，再读分布式系统章节。
完成后，检查自己能否区分“最后收到”和“最近发生”。

## 每篇怎样学习

1. 先阅读目标，挑一个自己能用建筑语言描述的问题。
2. 把核心机制中的对象、关系和规则画在纸上。
3. 运行唯一的 Python 实验；只有 Python 标准库，无需安装专业软件。
4. 对照 `text` 围栏的确切输出，再只修改一个输入观察变化。
5. 合上正文回答闭卷问题，最后展开答案检查解释是否完整。

实验中的断言只验证该实验声明的条件，不代表对任意工程数据的完整验证。
运行成功后，应能讲清楚结果成立的原因，而不只是得到相同数字。

## 纸面实验：选对问题入口

以下三个情境来自一座虚构的“示例建筑”，无需联网或运行程序。
每个情境选择一个最先阅读的分类，并写下最先检查的一项信息。

1. 两个叫“墙”的对象在合并表格时只剩一行。
2. 场地边界与建筑轮廓形状吻合，但整体方向和位置不同。
3. 一个旧温度值在新值之后到达，把屏幕读数覆盖了。

参考结果：

```text
1. BIM 与数据：检查用于合并的对象标识。
2. GIS 与坐标：检查坐标参考、轴向和变换。
3. 数字孪生：检查观测时间与到达顺序。
```

这道题检查问题分解，不要求某一种软件操作顺序。
实际任务可以同时涉及多类知识，例如 IFC 到 GIS 的转换也需要数据关系检查。
