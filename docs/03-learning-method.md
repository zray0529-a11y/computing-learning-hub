# 学习方法与掌握诊断

本指南面向计算机初学者；建筑与空间专业读者可以结合[建筑分类专题](../architecture/README.md)选择熟悉的场景。
领域经验可以提供理解入口，但不自动证明计算机基础已经掌握。
本文提供学习与判断掌握程度的方法。每位读者在自己的学习副本中保存证据，公共教材不记录任何个人的能力评分。

入口：[专栏首页](index.md) · [12 周建议计划](04-learning-plan.md) · [问题路由](05-question-routing.md) · [进度与复习](06-progress-and-review.md) · [练习目录](practice/index.md)

## 1. 学习闭环

学习目标写成可观察动作，例如“能预测循环结果并解释退出条件”，不要只写“理解循环”。

| 环节 | 学习者做什么 | 教学者观察什么 |
|---|---|---|
| 诊断 | 先解释或尝试一个微任务 | 前置概念、误解、帮助需求 |
| 建立模型 | 读最小解释与完整例题 | 能否说出输入、过程、输出 |
| 教回 | 解释为什么，并指出边界 | 因果联系是否准确 |
| 逐步练习 | 从补全过渡到独立完成 | 撤去提示后能否继续 |
| 检索 | 关闭材料，再回答或操作 | 能否提取而非仅仅认出 |
| 反馈 | 对照依据修正自己的答案 | 错误原因是否发生改变 |
| 迁移 | 换数据、约束或场景重做 | 是否会选择方法而非套步骤 |
| 延迟检查 | 下次学习时再次提取 | 保持情况与下一次复习需求 |

这套组合是本专栏的教学设计；研究支持其中若干原则，并未直接验证这一整套个性化流程。

## 2. 先诊断，再决定起点

每个主题先选 1—3 道短题，不把第一轮变成长考试。
允许直接说“不知道”；不知道帮助我们定位起点，不是学习失败。
优先检查当前任务需要的前置知识，遇到缺口再回到对应章节。

- 解释题：程序与算法有什么关系？能否给出一个不是计算机程序的算法例子？
- 预测题：一份相机清单中缺少设备编号，后续查询可能出什么问题？
- 操作题：给三条设备记录，筛选在线设备，并说明输入和输出。
- 边界题：“BIM 模型存在”是否足以说明数字孪生中的实时状态正确？为什么？

只依据实际回答、代码、操作结果和解释更新记录；不能从职位、项目名或“我懂了”推断会了。
如果问题只要求完成当前工作，先解决工作，再提供一个简短学习检查，不强迫进入整套课程。

## 3. 0—4 分只描述当前任务证据

| 标记 | 证据描述 | 接下来怎么做 |
|---|---|---|
| 未评估 | 尚无作答或操作证据 | 给最小诊断题；不计作 0 分 |
| 0 | 已尝试，但关键概念明显错误或无法开始 | 补一个前置概念，再给例题 |
| 1 | 看例题能辨认，依赖逐步指导复现 | 做单步补全并解释理由 |
| 2 | 能解释部分原理，借助提示完成近似任务 | 减少提示，检查关键误解 |
| 3 | 能独立解释并完成典型任务，核对结果 | 换数据或约束，安排延迟检查 |
| 4 | 能独立处理适度变式，说明选择、边界和检查方法 | 增加组合任务，继续观察保持 |

这是教学记录规则，不是标准化心理测量，也不等同于考试等级或永久掌握。
分别记录**解释、操作、迁移、延迟保持**；不要把几项平均成虚假的“掌握百分比”。
一项任务得到 4 分，不代表整章得到 4 分；会运行 AI 生成的程序，也不自动构成独立操作证据。
记录实际帮助程度：独立／轻提示／逐步指导／完整答案已给出。
环境安装失败与概念错误分开记录，不能因工具故障判定概念能力不足。

建议每条证据保留：日期、概念、题目、作答或产物、评分理由、提示程度、错误类型、下次检查。
示例只作格式演示：“函数｜独立写出筛选函数，漏测空列表｜操作 3｜边界检查待验证”。
记录方式见[进度与复习](06-progress-and-review.md)；上述内容仅为格式示例。

## 4. 教回：把“费曼式解释”变成可检查的活动

这里使用“费曼式教回”指用自己的话解释、暴露缺口、查证和重讲。
研究依据主要来自自我解释研究，不把“费曼学习法”品牌当成单独验证过的万能方案。[R1][R4]

1. 不看原文，用 3—5 句话解释概念要解决什么问题。
2. 指出输入、输出和关键因果关系；保留必要术语。
3. 给一个小例子，并解释每一步为什么成立。
4. 指出一个不适用情形或容易混淆的概念。
5. 对照可靠材料修正，再用新例子重讲。

自我解释强调推理与概念联系；仅把原文换词、讲得流畅或使用比喻，不能证明理解。[R4]
教学者先让学习者尝试，再补解释；每句话都由 AI 先讲完，会减少可观察的独立证据。

**建筑类比示例：API。**
可先把 API 理解为参与方约定的交付接口，再回到请求、响应、参数、错误和接口契约。
边界是：API 也可能只是同一程序中的函数接口，不一定经过网络，更不等于学习者界面。
检查题：“如果返回格式变了，调用方为什么可能失败？接口存在是否保证数据正确？”
类比用于进入概念；正式定义和反例负责限制类比。

## 5. 检索练习：先提取，再核对

检索练习指尝试从记忆中生成答案；它既能暴露缺口，也可帮助之后的保持。
短文实验中，重复阅读可能带来较好的即时表现和信心，而检索在延迟测验中更有优势。[R2]
因此不把“刚看完觉得熟悉”作为完成标准。

- 概念：关闭答案，解释进程与线程各自解决什么问题。
- 代码：先预测一段循环的输出，再运行并解释差异。
- 调试：看到错误信息，先提出一个可检验假设，再查资料。
- 架构：只给需求，画出数据从相机进入系统到被使用的路径。
- 选择：说明为什么此处用字典查设备，而不是按列表位置猜设备身份。

练习题和答案分开；先给题，学习者尝试后再展开解析。
失败后及时补学，再做一题；不要把持续猜测当作有效检索。
概念卡不能替代代码、数据处理、网络请求和调试等实际活动。

## 6. 间隔练习：按表现安排，不迷信固定日历

间隔练习把接触与提取分散到不同时间；其长期保持收益有较广泛研究支持。[R1]
适合的间隔与目标保持时间有关，并不存在适用于所有内容和人的统一最佳天数。[R3]

| 本次表现 | 下一次安排的默认思路 |
|---|---|
| 关键错误、完全想不起 | 本次先补学并再试；下一次学习优先回访 |
| 提示后能完成 | 较早再给同原理的新题，逐步撤掉提示 |
| 独立完成但解释不稳 | 保持较短间隔，增加解释和反例 |
| 独立完成且变式稳定 | 逐步拉长间隔，纳入之后的项目任务 |

可从“下次学习时—约一周后—更久以后”试行，但这是可调整的实践起点，不是科学固定处方。
复习先检索再看笔记；每次不必整章重读，只补当前证据显示的缺口。
本文件不创建自动提醒；具体学习日期与提醒需另行安排。

## 7. 交错练习：练习辨别该用什么

交错把相关但不同的题型或概念穿插练习，目标是让学习者判断该选哪种方法。
元分析显示收益依材料而变，不能把混学任何内容都当作更有效；词语和说明性文本需谨慎。[R5]

- 先分别学习列表与字典，再混合“保持顺序”和“按编号查询”的需求。
- 先分别学习相机内参与外参，再判断一个问题涉及成像参数还是空间位姿。
- 先分别学习本地函数与网络请求，再比较超时、错误和重试的处理。
- 每次回答除了结果，还要说“我根据什么判断属于这一类”。

新概念尚未建立基本模型时，先做少量同类题；随后加入旧概念，避免无关主题随机跳转。
上述计算机任务是教学应用建议，不是相关元分析直接测试过的全部场景。

## 8. 例题渐隐：从看懂走向独立做

先看完整例题，再补全缺失步骤，最后独立解决问题。
渐隐研究对初期结构化技能和近迁移有支持，远迁移收益不能自动保证。[R6]

贯穿例题：“读取三台相机的设备记录，筛选在线设备，输出设备编号。”

| 阶段 | 给出的支持 | 学习者承担的工作 |
|---|---|---|
| 完整例题 | 输入、代码、结果和逐步说明 | 预测结果，解释每步目的 |
| 单步补全 | 保留大部分过程，省去最后一步 | 写出输出逻辑并核对 |
| 多步补全 | 只给数据格式、函数入口和预期行为 | 完成筛选、输出与边界处理 |
| 独立任务 | 只给新数据与要求 | 选择结构、实现、检查、解释 |
| 迁移任务 | 加入缺失字段或不同筛选条件 | 修改规则，说明旧解法哪里失效 |

撤去支持应依据表现，而非机械按题数推进；明显卡住时只恢复必要的一层提示。
看懂例题是起点；熟练之后应增加独立实践，避免长期跟抄。

## 9. 反馈：具体、可修正、再验证

反馈指出“哪一步、为什么、如何检查”，不只给正确答案或笼统评价。
选择题研究发现，提供正确答案反馈可减少后续重复错误；该证据不等于所有反馈时机都相同。[R7]

1. 先让学习者说明预测、理由或代码意图。
2. 用标准定义、反例、运行结果或可复现检查定位差异。
3. 提供最少必要提示：目标提醒→相关概念→局部步骤→完整示范。
4. 让学习者修正自己的答案，再解释变化。
5. 换一道同原理小题，检查是否只记住本题答案。

错误可分为概念误解、表示或单位错误、步骤错误、边界遗漏、工具环境问题。
例如“米与毫米混用”应修正数据契约与检查方法，而不只是把一个结果改小一千倍。
AI 的解释本身也需核对；版本、API 行为和安全相关结论优先查官方资料或直接验证。

## 10. 迁移与延迟保持：分别检查

迁移检查回答“换个情形还能用吗”，延迟检查回答“过段时间还能提取吗”。
检索实验观察到对新推理问题的迁移，但不能据此保证复杂软件项目中的普遍迁移。[R8]

- 近迁移：把三台相机换成十台，沿用同一筛选原理。
- 适度变式：加入缺失状态、重复编号和未知值，重新说明约束。
- 场景迁移：把设备筛选换成建筑构件筛选，解释哪些结构可以复用。
- 组合任务：将获取、校验、存储、查询和展示连接起来，并定位故障。
- 延迟检查：在后续会话先做一题，记录是否独立完成，不提前展示旧答案。

每次只增加少量变化，便于判断失败来自哪个概念；复杂任务失败后回退到最小可检查环节。

## 11. 一次约 30 分钟的默认会话

| 时间 | 活动 | 留下的证据 |
|---|---|---|
| 3 分钟 | 检索一个旧概念、确认本次目标 | 原回答与缺口 |
| 7 分钟 | 最小解释、完整例题、一次教回 | 因果解释与疑问 |
| 12 分钟 | 补全题到独立小任务 | 代码、操作或图示 |
| 5 分钟 | 反馈后做一题变式 | 修正与迁移表现 |
| 3 分钟 | 记录证据、安排下次回访 | 下一步与待验证项 |

时长可调整；如果前置概念不足，宁可缩小本次目标，也不靠增加术语赶进度。
进入下一主题前，以[学习计划](04-learning-plan.md)的先修门槛和实际证据决定。

## 12. 研究来源与阅读边界

以下来源于 2026-11-15 核对；访问方式包括搜索服务返回的论文正文、作者页面与出版社摘要，仅阅读表中列出的部分，全文链接的直接下载条件可能变化。
研究结论、理论解释和本文的教学设计建议要区分；不使用“教别人记住 90%”等无依据记忆率。
这些研究多数没有直接研究当前学习者或完整计算机项目，实际收益需靠持续记录检验。
