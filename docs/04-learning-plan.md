# 12 周建议学习计划

本计划用于建立计算机与智能系统的基础框架，并完成一个可以解释、检查和修改的小项目。
每周建议 **3—4 次、每次 25—40 分钟**；可根据工作负荷、已有经验和诊断结果调整。
“第几周”是建议学习单元，可以跨周完成；12 周不是完成承诺，也不代表覆盖完整计算机专业课程。
每位读者从自己的起点诊断开始；计划表只列教学单元，不记录公共的个人学习状态。实际日期、复习与提醒由读者自行安排。

入口：[专栏首页](index.md) · [学习方法](03-learning-method.md) · [问题路由](05-question-routing.md) · [进度与复习](06-progress-and-review.md) · [练习目录](practice/index.md)

## 1. 每周节奏与最低产物

| 会话 | 主要活动 | 最低产物 |
|---|---|---|
| A：建立模型 | 检索旧概念，诊断先修，读最小解释与例题 | 一段自己的解释与一个待验证问题 |
| B：撤去提示 | 补全任务，逐步过渡到独立实现 | 一段代码、数据处理结果或可核对图示 |
| C：检查迁移 | 换数据或约束，反馈后再试 | 一道独立变式题和一条错误修正 |
| D：可选 | 回访旧主题，整理记录或处理项目问题 | 一条延迟保持证据或项目改进 |

每次优先完成一个明确目标；不足 25 分钟时可做一题检索和一个局部修正，不必放弃整周。
知识库笔记、AI 给出的答案和工具运行成功均不自动计作独立能力证据。
记录任务与帮助程度；具体 0—4 分规则见[学习方法](03-learning-method.md)的第3节。

## 2. 先修门槛与跳测规则

门槛只服务于下一项任务；暂时不达标时回补缺口，不重新学习整章。
“达到门槛”默认指能够独立解释并完成对应典型微任务，接近方法文档中的 3 分证据。

| 门槛 | 检查任务 | 用于哪些后续内容 |
|---|---|---|
| G0：表示与输入输出 | 区分对象、记录、字段、编码；说明任务的输入与输出 | 所有章节 |
| G1：基本程序 | 写一个筛选函数，解释条件、循环和返回值，检查空输入 | 数据库、工程、ML、Agent 实作 |
| G2：运行与通信 | 区分进程、文件、请求和响应；定位一个失败步骤 | 网络、分布式、服务编排 |
| G3：数据与工程 | 按稳定标识查询数据；能保存修改并重做一项检查 | 分布式、贯穿项目 |
| G4：基础数学 | 解释比例、平均数、条件概率的直觉和向量的意义 | ML、相机几何与评估 |
| G5：模型与证据 | 区分预测输出、检索资料、规则判断和实际执行结果 | LLM、Agent、安全复盘 |

- 有相关经验时，先做解释题和独立任务；两者都稳定，再用一个变式题确认可跳过讲解。
- 跳测只缩短已验证部分；未测的维度仍标为未知，不因为项目经验直接判定整章掌握。
- 提示后做出的结果按实际帮助程度记录；可以从补全阶段开始，无须重复最基础示范。
- 实作受环境限制时，先做纸面预测或数据检查，并把“独立运行未验证”留在记录中。
- 每周离开当前单元前，检查退出门槛；未通过就缩小任务或增加一轮练习。

## 3. 贯穿项目：相机事件到可追溯的空间记录

默认项目使用人工编写的少量示例数据，模拟“设备产生事件→校验→存储→查询→解释→待确认动作”。
起初只需设备编号、时间、区域、事件类型和状态；每周仅增加当前概念需要的一小层。
已有相关项目可作为题材，但学习产物应保持足够小，以便明确判断哪些步骤由自己完成。
实机视频接入、生产系统写入和高后果自动执行不是完成此基础计划的必要条件。

## W1：基线、信息表示与可计算性

- 阅读：[可计算性与信息](chapters/01-computation.md)；进入门槛：无须预先证明任何计算机基础。
- A：用三道小题检查“信息与载体、输入输出、程序能解决什么”，如实记录未知和已有证据。
- B：把同一台相机表示为文字、表格和结构化记录，说明各字段的意义、单位与缺失值。
- C：区分“任务描述不清”“有明确算法但成本高”“存在理论计算边界”，用小例子解释。
- 可选 D：教回“数字表示为什么不等于物理世界本身”，回访一个基线误解。
- 产物与退出门槛：一份设备记录及说明；能区分对象、数据、表示和计算过程，满足 G0。
- 跳测或回补：能完成则压缩讲解；若字段、编码或逻辑概念不稳，先补这三个入口。

## W2：程序与算法

- 阅读：[程序与编程](chapters/03-programming.md)、[算法与数据结构](chapters/04-algorithms.md)；进入门槛：G0。
- A：从“筛选在线相机”例题学习变量、条件、循环、函数，并逐步预测输出。
- B：先补全过滤步骤，再独立写筛选函数；比较按顺序遍历和按编号查询的需求。
- C：处理空列表、重复编号或缺失状态；说明算法步骤和数据结构为什么适合。
- 可选 D：用手工执行轨迹比较不同规模输入，建立成本随规模变化的直觉。
- 产物与退出门槛：可重复运行的小函数及至少一个边界检查；解释输入、输出和退出条件，满足 G1。
- 跳测或回补：已有脚本经验者直接做变式；只会复制运行者回到单步补全和输出预测。

## W3：硬件与操作系统

- 阅读：[计算机硬件](chapters/02-hardware.md)、[操作系统](chapters/05-operating-systems.md)；进入门槛：G0，并能运行或逐步解释一个小程序。
- A：追踪程序从文件到运行过程，区分 CPU、内存、存储和输入输出。
- B：观察一个进程与一个文件读写任务；解释路径、工作目录和资源的作用。
- C：对比文件不存在、内存不足、程序等待外部数据三类现象，提出可检查的假设。
- 可选 D：解释为什么“文件仍在磁盘上”和“程序当前正在运行”是不同状态。
- 产物与退出门槛：一张运行路径图和一份故障定位记录；能说明程序、进程和文件的关系，建立 G2 的运行部分。
- 跳测或回补：熟悉命令行者直接做故障题；不熟悉者先练路径与运行位置，不强行堆叠命令。

## W4：网络与接口

- 阅读：[网络与通信](chapters/06-networks.md)；进入门槛：G0，以及 G2 的程序运行部分。
- A：追踪一次请求的发起、地址解析、连接、响应与解析，区分接口契约和网络传输。
- B：检查一个示例请求与响应，指出方法、地址、状态及数据；有环境时实际发送一次读取请求。
- C：分别分析连不上、超时、响应报错和格式不符合预期，应在哪一层寻找证据。
- 可选 D：教回“本地函数调用与网络请求有什么相同与不同”，回访程序输入输出。
- 产物与退出门槛：一份请求响应说明和故障分层图；能定位失败阶段，补齐 G2。
- 跳测或回补：已有 API 经验者直接做异常场景；记不清数据结构时回到 W2 的记录解析。

## W5：数据库与数据建模

- 阅读：[数据库](chapters/07-databases.md)；进入门槛：G0、G1；至少能说明稳定设备标识的用途。
- A：从设备与事件区分实体、属性和关系，讨论为何不能用列表位置作为永久身份。
- B：建立最小设备表与事件表，完成按设备和时间范围查询。
- C：加入重复事件或缺失关联，解释唯一性、约束和一次完整写入的要求。
- 可选 D：把同样的建模思路迁移到建筑构件与巡检记录，说明差异。
- 产物与退出门槛：小型表结构、示例数据和查询结果；能解释查询与约束，完成 G3 的数据部分。
- 跳测或回补：熟悉表格不自动等于数据库经验；可通过关系与异常数据题跳测。

## W6：软件工程、Git 与测试

- 阅读：[软件工程](chapters/08-software-engineering.md)；进入门槛：G1，并能说明当前项目的数据流。
- A：把一个需求写成可观察行为，区分正常输入、边界条件和失败行为。
- B：完成一次小改动，查看差异并保存版本；给筛选或校验逻辑添加有意义的检查。
- C：重现一个故障，写清复现条件，修正后重跑相关检查。
- 可选 D：让另一位读者或未来的自己按说明重做；记录环境与操作依赖。
- 产物与退出门槛：一条清楚的修改记录、运行说明和检查结果；能重做修改并解释检查价值，补齐 G3。
- 跳测或回补：已有 Git 使用经验者直接做“识别误改与恢复思路”题；不要求背全部命令。

## W7：分布式系统

- 阅读：[分布式系统](chapters/09-distributed-systems.md)；进入门槛：G2、G3。
- A：把获取、处理和存储拆成独立角色，说明局部失败为什么会出现。
- B：模拟事件重复、乱序和处理延迟；为事件增加标识，讨论重复处理的结果。
- C：设计一次重试，说明怎样判断操作是否已经成功，以及如何避免不希望的重复效果。
- 可选 D：对比“全部正常”和“一个组件暂时不可用”时的可观察状态。
- 产物与退出门槛：一张事件流图及一份故障表；能解释超时、重试、幂等与一致性的关系和边界。
- 跳测或回补：已有系统集成经验者直接处理重复与乱序；通信或数据约束不稳则回 W4、W5。

## W8：数学、统计与机器学习

- 阅读：[数学、统计与机器学习](chapters/10-math-and-ml.md)；进入门槛：G1；先诊断 G4，不默认数学已会。
- A：检查比例、平均数、条件概率和向量直觉；仅补当前任务需要的缺口。
- B：用少量标注事件区分输入特征、标签、训练与评估，建立一个可解释的简单基线。
- C：比较漏报与误报，说明不同阈值的取舍；检查评估资料是否泄露到训练或规则制定中。
- 可选 D：把评估结论改写为有适用范围的句子，列出样本不足或场景变化带来的疑问。
- 产物与退出门槛：一个评估表和对结果的解释；区分预测、事实和误差，建立 G4、G5。
- 跳测或回补：数学基础强者直接做数据与评估题；若概率或向量不稳，可将本单元拆为两周以上。

## W9：LLM 与 RAG

- 阅读：[大语言模型与 RAG](chapters/11-llm-and-rag.md)；进入门槛：G0、G2，并能区分模型预测与已核实事实。
- A：解释上下文、生成、检索资料与回答之间的关系，区分训练时知识和本次提供的信息。
- B：为几条设备说明建立最小检索问答，保留问题、检索片段、回答和出处。
- C：加入资料缺失、过时或互相矛盾的问题，检查系统如何表达不确定性与定位证据。
- 可选 D：对比直接提问与提供相关资料后的回答，分析错误出现在哪一环。
- 产物与退出门槛：一组可检查的问答样例；能追踪回答依据，并说明检索不能自动保证回答正确，强化 G5。
- 跳测或回补：经常使用聊天模型者仍需做证据与失败题；基础相同可跳过界面操作。

## W10：推理、工具调用与 Agent

- 阅读：[推理与 Agent](chapters/12-agents.md)；进入门槛：G1、G2、G5。
- A：区分模型给出的文字、结构化工具请求、工具执行结果和外部实际状态。
- B：设计“查询事件→检查条件→提出下一步”的小工作流，每步明确输入、输出与停止条件。
- C：模拟工具失败或信息不足，说明重试、退出、升级给人的条件；用外部结果验证动作是否成功。
- 可选 D：比较固定工作流与由模型选择下一步的方案，说明各自需要检查什么。
- 产物与退出门槛：一份流程与执行记录；能区分建议、调用与完成，解释权限边界和终止规则。
- 跳测或回补：已有 AI 编排经验者直接诊断失败路径；不会解释接口数据时回 W4，而非增加 Agent 层数。

## W11：安全、可靠性与空间场景

- 阅读：[安全与可靠性](chapters/13-security-and-reliability.md)、[空间系统](chapters/14-spatial-systems.md)；进入门槛：G2—G5 的相关部分。
- A：为当前项目标出信任边界、访问权限和可观察记录，区分输入数据与可执行指令。
- B：检查设备、区域和空间对象的关联，核对坐标系、方向、单位、时间和状态语义。
- C：模拟一个错位、过期或权限不足的事件，说明系统怎样发现、限制影响并给出复核证据。
- 可选 D：从相机观察到业务状态逐层教回，指出哪些判断仍需要额外数据或人工确认。
- 产物与退出门槛：一份空间数据契约和三个故障案例；能追踪事实来源，解释边界与恢复路径。
- 跳测或回补：建筑经验可帮助对象与空间理解；坐标变换、概率判断和权限机制分别检查。

## W12：贯穿项目与复盘

- 阅读：按问题回访前面各章，并参考[问题路由](05-question-routing.md)；进入门槛：项目涉及的 G0—G5，不要求无关分支都已完成。
- A：从空白说明开始，独立画出“输入→校验→保存→查询→解释→待确认动作”的数据流。
- B：重做最小项目，保留运行说明和检查依据，标注仍需提示或未独立验证的部分。
- C：改变一种需求或加入一种故障，修改方案；向“懂建筑但不懂计算机的人”解释并回答反例。
- 可选 D：回访 W1、W2、W4 的旧题，记录延迟保持，比较基线证据与当前表现。
- 产物与退出门槛：可重做的小项目、变式结果、概念关系图和下一阶段缺口清单；不以页面数量验收。
- 跳测或回补：若项目过大，缩成单文件数据处理与说明；只对实际展示过的能力下结论。

## 5. 如何调整和继续

每周结束只做三项决定：哪些证据足够、哪一处缺口先补、下一次检查什么。
工作中遇到真实问题时可按[问题路由](05-question-routing.md)进入对应章，再回到主线补先修。
落后一周无需补做所有阅读；保留核心任务、独立变式和延迟回访，删减重复讲解。
已有经验使进度更快时，把时间用于边界、错误处理和跨章迁移，不只增加阅读量。
12个单元完成后，根据实际证据选择深入软件工程、AI系统或空间计算。建筑专业读者还可选择[BIM与数据、参数化设计、GIS与场地、数字孪生与运维](../architecture/README.md)。

## 6. 方法依据与边界

本计划采用的检索、间隔、自我解释和例题渐隐依据，见[学习方法的研究来源](03-learning-method.md#12-研究来源与阅读边界)。
Dunlosky 等（2013）的[综合综述](https://journals.sagepub.com/doi/pdf/10.1177/1529100612453266)支持优先安排检索与分散练习。
Cepeda 等（2008）的[间隔实验](https://www.yorku.ca/ncepeda/publications/CVRWP2008.pdf)说明合适间隔依目标保持时间而变，不支持统一固定复习日历。
研究没有验证“上述主题必须按 12 周完成”；周次、时长、门槛与贯穿项目均为可修改的教学设计。
