# 贯穿验收项目：相机模拟观察 → 实体状态 → 查询

项目问题是：收到一些可能重复、乱序、缺失或过期的观察后，我们能向一个请求者返回什么？
答案必须保留观察时间与证据；资料不足时返回 unknown，权限不足时返回 denied。
所有数据都是人工构造的模拟记录，不来自真实相机、人员、建筑或生产系统。
参考脚本提供可运行示范；学习者通过自己的实现、修复、迁移与复盘形成学习证据。
每位学习者可复制[进度模板](../06-progress-and-review.md)到本地，依据自己的实际表现填写。

入口：[六个最小实验](01-labs.md) · [参考脚本](lab.py) · [进度与复习](../06-progress-and-review.md) · [专栏首页](../index.md)

## 1. 最小范围与参考实现

参考数据流为 fixture → build_index → latest_observation／retrieve → workflow。
“实体状态”在本项目中严格解释为“最近有效模拟观察的状态”，不等于此刻物理世界的真实状态。
查询同时返回 observed_at、as_of 和 evidence_ids，让回答保留时间和来源边界。
工作流最多提出待复核建议，不改变真实世界，也不执行外部动作。
SQLite 实验独立演示参数绑定和事务；贯穿数据流目前使用内存字典，没有暗中接入生产数据库。

| 参考实现提供的内容 | 学习者任务 |
|---|---|
| 代码内虚构输入与统一模拟时钟 | 自己解释每个字段和时间规则 |
| 身份索引、重复忽略、冲突隔离 | 独立实现同类规则或修复练习副本 |
| 授权、时间筛选、最新观察与关键词命中 | 为新实体、新约束设计变式 |
| 有预算的确定性工作流与证据检查 | 说明为什么不足以代表自主 Agent |
| 明确的示例输出 | 提供自己的预测、错误修正和掌握证据 |

右列任务的结果由每位学习者在本地记录。独立通过应有新题作答或迁移证据；打开文档、运行参考程序或得到 AI 完整答案，不能单独证明掌握。

## 2. 输入数据契约

实验 1 的设备清单与下面的观察事件是两种结构：前者练习字段解析，后者用于贯穿项目。
事件编号标识一次观察；实体编号标识被观察的空间区域；相机编号标识模拟来源。

| 字段 | 类型与约束 | 示例与用途 |
|---|---|---|
| event_id | 非空字符串；同一编号的载荷必须一致 | e2，用作事件身份与去重键 |
| camera_id | 非空字符串 | camera-sim-1，仅表示模拟来源 |
| entity_id | 非空字符串，按完整值精确匹配 | zone-a，用于归属与授权过滤 |
| observed_at | 非负整数模拟秒；布尔值、字符串和缺失值不合格 | 900，表示观察发生的时间 |
| state | clear 或 occupied | 仅为示例状态词，不是识别模型输出 |
| 到达顺序 | 由列表位置表示，与观察时间不同 | e0 可以在 e2 之后到达 |

空或缺失字段不会被猜成正常值；不合格事件被拒收并计入 invalid。
同 event_id 的完全相同载荷只保留一份；同 ID 的不同载荷被隔离，不能靠“最后一条覆盖”决定。
参考校验面向这些简单标量字段；没有实现通用 JSON Schema、真实相机身份验证或签名验证。

## 3. 时间与状态契约

- now 固定为 1000，TTL 固定为 600；二者和 observed_at 使用同一模拟时钟与秒单位。
- 这不是 Unix 时间戳，没有日期、UTC 或本地时区，也不读取系统当前时间。
- 年龄 age = now - observed_at；只有 0 <= age <= TTL 的记录进入有效观察集合。
- 因此 observed_at=400 恰好有效，399 已过期，1001 在未来并被排除。
- 同一实体先按观察时间找最大值；到达顺序不决定最近状态。
- 最新时刻存在互相矛盾的状态时返回 unknown，而不是按编号或列表位置任选一条。
- 即使符合 TTL，也只能陈述某时刻的模拟观察；TTL 是示例策略，不证明现实中的状态一直未变。

缺失时间、过期记录和未来记录都不能支持当前有效观察；参考查询统一给出 no_fresh_observation。
若以后需要分别说明失败原因，应保留校验与筛选的原因记录，这是扩展任务，当前未实现。

## 4. 授权、证据和结果契约

授权集合在脚本 ALLOWED 中明确给出；zone-secret 不在其中。
请求先通过实体授权检查，再接触该实体的记录；越权返回不包含事件内容或证据编号。
授权只能说明“可以查看什么”，不说明“记录是否新鲜、是否正确”，这些条件需分别检查。

| status | 精确含义 | 不应据此推断 |
|---|---|---|
| observed | 找到最近有效且不矛盾的模拟观察 | 此刻物理实体状态必然如此 |
| matches | 找到满足范围、时间与关键词条件的记录 | 命中内容就是最近状态或正确答案 |
| unknown | 证据不足、矛盾或预算耗尽等 | 实体状态为 clear，或一定不存在事件 |
| denied | 请求的实体不在允许集合 | 该受保护实体是否真实存在 |
| ready_for_review | 工作流得到有依据的待复核建议 | 已执行真实动作或获得额外权限 |

工作流支持证据的条件是：声明与同一授权实体的最近有效观察一致，且证据编号非空并匹配。
它不相信一段孤立的状态文字；剥离证据后，即使状态词看起来合理，也返回 unknown。
这只是函数调用边界上的策略演示；源码本身包含全部虚构数据，不构成可部署的访问控制系统。

## 5. 默认输入中的关键场景

| 事件或场景 | 实体 | 观察时间 | 预期处理 |
|---|---|---:|---|
| e1：clear | zone-a | 500 | 仍有效，但不是最近观察 |
| e2：occupied，另有完全相同重发 | zone-a | 900 | 一份有效事件，作为最近观察证据 |
| 较晚到达的 e0：clear | zone-a | 450 | 不能覆盖 e2 |
| e-old | zone-old | 399 | 过期，不能支持 observed |
| e-future | zone-future | 1001 | 未来，不能支持 observed |
| e-missing | zone-missing | 缺失 | 校验拒收，查询为 unknown |
| e-edge | zone-edge | 400 | TTL 边界包含此记录 |
| e-c1 与 e-c2，状态相反 | zone-conflict | 均为 950 | 最新观察矛盾，返回 unknown |
| e-private | zone-secret | 990 | 无权限请求得到 denied |
| 单独的同 ID、不同状态样例 | zone-a | 500 | 实验 2 隔离冲突 ID |

## 6. 验收矩阵：先知道要证明什么

下面的矩阵用于核对参考脚本的行为；学习者可另用独立变式记录掌握情况。
运行方式：在本目录执行 python3 lab.py，或使用 --lesson 1 至 --lesson 6。
“对应输出”可在[实验文档的折叠答案](01-labs.md)与实际运行中核对。

| 验收条件 | 输入或触发方式 | 对应输出与判据 | 范围 |
|---|---|---|---|
| 类型不能靠真假值猜 | online="false" 或缺失 | 实验 1：cam-c、cam-d 在 invalid_ids | 字段解析 |
| 同一事件不重复产生模拟效果 | e1 完全重发 | 实验 2：effect_count=2，duplicates_ignored=1 | 内存唯一记录计数 |
| 相同 ID 不静默覆盖 | 相同 e1、不同 state | 实验 2：id_conflicts=1，结果 unknown | 身份一致性 |
| 失败事务撤销本事务写入 | 插入 e2 后触发 e1 主键冲突 | 实验 3：row_count=1，只剩已提交 e1 | 内存 SQLite |
| 查询值不能改变 SQL 结构 | 查询值含引号与 SQL 片段 | 实验 3：injection_text_query=[] | 值使用参数绑定 |
| 乱序旧事件不覆盖新观察 | e0 在 e2 后到达 | 实验 4：zone-a 的证据仍为 e2、时间 900 | 事件时间选择 |
| 旧、未来、缺失观察不被冒充有效状态 | 399、1001、缺失时间 | 实验 4：三个对应实体均 unknown | 固定时钟规则 |
| 时间边界明确 | 观察时间 400 | 实验 4：zone-edge 为 observed | 包含 TTL 端点 |
| 矛盾不伪装成确定答案 | 同一最新时刻两种状态 | 实验 4：zone-conflict 为 unknown | 简单冲突策略 |
| 越权资源不返回 | 请求 zone-secret | 实验 5：denied、hits=[]；实验 6：attempts=0 | 模拟授权边界 |
| 关键词命中不等于最近状态 | zone-a 检索 clear | 实验 5：命中 e1、e0，最近观察仍是 occupied | 检索与判定分开 |
| 有文字但没证据时不通过 | strip_evidence=True | 实验 6：insufficient_evidence、unknown | 证据检查 |
| 重试有停止条件 | 预算 2，连续模拟超时 3 次 | 实验 6：attempts=2、budget_exhausted | 有界重试 |
| 预算为零不执行尝试 | budget=0 | 实验 6：attempts=0、unknown | 预算边界 |

本脚本没有真实业务副作用；去重验收只说明这个内存模型的效果计数，不证明跨进程或外部系统的 exactly-once。
参数化示例保护查询值；不演示动态表名、权限数据库或完整 Web 应用安全。

## 8. 独立变式题

先自行提出预期和检查方式，再查看参考代码；把解答、实际输出和修正理由保存在自己的本地记录中。

1. **新的实体**：增加 zone-b 的两条观察，保持 zone-a 查询结果不受影响。
2. **新的时钟**：将 now 推进到 1501，列出原有证据哪些失效，避免沿用上次答案。
3. **不同授权**：只允许 zone-edge；说明 zone-a 和一个未知、未授权编号应分别返回什么。
4. **不同重试预算**：预算为 1，首个尝试失败；给出停止结果，不把失败改写成正常状态。
5. **错误证据**：构造状态相同、但证据属于另一个实体的声明，说明为什么不能接受。
6. **新业务问题**：从“最近观察”改成“某时间段出现过哪些事件”，重新定义查询，避免混用两个问题。

迁移完成后，再解释哪些规则可用于建筑构件巡检，哪些必须因为领域、单位或状态含义变化而重写。
若把练习扩展为保存文件、接入实时相机或执行动作，应重新设计数据生命周期、权限与验收；参考脚本的范围仍是离线模拟。

## 9. 运行验证与证据边界

参考脚本在 2026-11-15 使用 Python 3.12.14、SQLite 3.53.1 运行六个默认实验，退出码为 0。
验证关注内置情形下的输出、数据边界与停止条件；不据此保证所有输入、平台或未来扩展都正确。
各实验使用标准库；程序没有网络请求、文件输出、外部数据库地址、密钥读取或真实动作调用。
同一脚本默认结果可预测；错误注入练习需在副本中进行，不能用被故意改坏的副本覆盖参考验收结论。

本项目没有图像识别、几何标定、真实流处理或设备接入，也没有处理真实时钟漂移、并发与持久化恢复。
实验 5 是关键词与规则筛选；它不能说明 embedding 效果、检索召回率、生成真实性或真实 RAG 性能。
实验 6 是确定性分支和模拟超时；它不能证明 LLM 推理质量、自主规划、真实工具可靠性或端到端 Agent 能力。
这些边界用于定义下一阶段任务，避免把演示输出当成已完成的真实系统。
