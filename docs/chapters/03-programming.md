# 03｜编程：用抽象组织可执行的规则

> **一句话核心：编程是把需求写成可检查、可组合、可执行的规则。**

图解把上次心跳 `last_seen = 100`、当前时间 `now = 131` 和阈值 `limit = 30` 交给一个判断函数，单位都是秒。它计算 `131 − 100 > 30`，得到 `True`（真），把这个结果交回调用它的程序；**这一步还没有发送告警**。
本章先读懂这个函数，再理解变量如何指向数据、怎样重复处理记录，以及如何把“作出判断”和“执行动作”约定清楚。不要求一次记住所有 Python 写法。

## 先修与学习目标

先理解[表示与逻辑](01-computation.md)以及[存储程序](02-hardware.md)。
只需读懂顺序、条件与重复；遇到不熟悉的符号，先问它表达什么关系。
学完应能解释一个函数的输入、输出、副作用、前置条件和失败方式。

## 语法起步：先把符号读成动作

程序像一份按顺序执行的操作说明。先认识下面几种写法，后面的例子就不必靠猜：

| 写法 | 先这样读 |
|---|---|
| `now = 131` | 先得到右边的值，再让左边的名字指向它；`=` 是赋值，`==` 才是判断相等 |
| `cameras = ["cam-01"]` | 建一个按顺序放数据的列表，并给它起名；引号里的内容是文字，`[]` 表示空列表 |
| `cameras.append("cam-02")` | 给这个列表的末尾添加一项；点号表示使用这个列表提供的操作 |
| `def is_stale(...):` | 定义一个函数，也就是可重复调用的一段规则；括号里列出它要接收的输入名字 |
| `return ...` | 计算后面的结果，结束本次函数调用，并把结果交回调用者 |
| `if`、`for`、`while` | 分别表示“条件成立才做”“逐个处理”“条件成立就继续重复” |

冒号后缩进的语句属于同一组；`#` 后面是给人看的注释。定义函数只是准备好规则，写下函数名和本次要传入的具体值，例如 `is_stale(100, 131)`，才会调用它。
下面的 `limit=30` 表示第三个输入的默认值是三十；调用时只给两个数，就采用这个默认值：

```python
def is_stale(last_seen, now, limit=30):
    return now - last_seen > limit  # 只计算是否超过阈值

result = is_stale(100, 131)
print(result)  # 显示返回结果，不发送告警
```

预期输出：

```text
True
```

把 `131` 改成 `130` 前先预测：相差恰好三十秒，`>` 不成立，所以结果会是 `False`（假）。函数、条件和循环的完整规则见 [Python 控制流教程](https://docs.python.org/3/tutorial/controlflow.html)，列表操作见[数据结构教程](https://docs.python.org/3/tutorial/datastructures.html)。

## 关键术语：从数据到模块

- **变量（variable）**：程序中用于引用或保存值的机制；具体含义由语言决定。
- **对象（object）**：Python 中承载数据的实体，具有身份、类型和值。
- **类型（type）**：说明值的类别与允许的操作，帮助约束程序行为。
- **函数（function）**：把一段计算封装成可调用单元，接收参数并返回结果。
- **作用域（scope）**：一个名字可以被查找和使用的程序区域。
- **副作用（side effect）**：除返回值外，对共享数据、文件、网络等造成的变化。
- **接口与契约（interface / contract）**：约定如何调用，以及输入、输出和错误必须满足什么条件。

## 机制一：变量不是万能的“盒子”

如果把相机清单交给另一段代码，对方加一条记录后，自己的清单为什么也变了？关键在于，交过去的可能只是同一份数据的另一个名字。
在 Python 中，可以把**列表对象**想成一个储物柜，把 `a`、`b` 想成贴在柜子上的两张标签。名字绑定到对象，就像贴标签；沿名字找到对象，就是使用它的**引用**。
执行 `a = []` 创建一个空列表并绑定名字；执行 `b = a` 后，两张标签贴到同一个柜子上，不会自动再造一个柜子。
名字绑定见 [Python 执行模型](https://docs.python.org/3/reference/executionmodel.html)。

因此，通过 `b.append("cam-01")` 给列表追加一项，也会从 `a` 观察到这项数据。
但若随后执行 `b = []`，只是让 `b` 指向另一个列表，不会清空原来的列表。
区分“改变对象”与“改变引用”，才能理解共享数据和许多难找的修改问题。
**类比边界：** 标签表示程序里的名字与对象关系，不表示变量名就是物理地址；重新贴标签与修改柜子里的内容是两件事。

整数、字符串等对象不可变，列表、字典通常可变；这里讨论的是对象的行为，而不是变量名能否再次赋值。
详见 [Python 数据模型 §3.1](https://docs.python.org/3/reference/datamodel.html)。
也不要把 Python 的规则机械套给所有语言；有的语言更强调固定类型的存储位置和值复制。

## 机制二：类型约束操作，但业务含义还要表达

数值 `3` 与文本 `"3"` 看起来相近，却支持不同操作：两个数字相加得到六，两个字符串拼接得到“33”。
程序必须在接收外部数据时决定是否转换，以及转换失败怎样处理。
类型系统帮助排除某些错误，却无法自动知道“三米”被误当成“三毫米”。

Python 的类型属于对象，很多检查发生在运行时。
**类型标注**是在代码中写下预期类型的说明，可以帮助阅读和**静态检查**（不实际运行程序，先分析它是否可能有错），但标注本身不会在调用时自动验证输入，见 [Python typing 说明](https://docs.python.org/3/library/typing.html)。
所以，面向相机治理的接口仍要明确：记录事件时间的数值即**时间戳**用秒还是毫秒，空值是否允许，编号能否重复。

这种约束就像尺寸标注：只有数字，没有单位和适用范围，图纸仍然不完整。
类型不是越复杂越好，而是应让常见误用更难发生，让错误更早被发现。

## 机制三：函数是可组合的计算边界

回到图中的“超过三十秒没有心跳就认为过期”。把 `last_seen`、`now` 和 `limit` 作为**参数**（函数接收输入时使用的名字），函数只返回判断结果，就能在不同设备和不同时间上复用。
若函数偷偷读取当前时间、直接发送告警并修改数据库，调用者就更难独立预测它的结果。

返回判断像交回一份审图意见；发送告警像按约定实际通知现场。这里的**副作用**是返回结果之外可观察的变化，例如修改共享清单、写入文件或发送网络消息。
返回值与副作用可以在同一次调用中同时存在，必须看函数的实现和契约，不能只看名字。
**类比边界：** 返回值并不天然“只读”。函数也可以返回一个可变列表，甚至返回与别处共享的列表；`return` 不会自动复制或冻结它。可变性取决于对象类型，而不是它是否由函数返回。

系统最终总要读取设备、保存数据、执行动作。
有用的做法是让判断规则和外部动作拥有清晰边界：先计算“应当告警吗”，再决定如何发送、记录和重试。
这样既容易用固定输入检查规则，也容易为不同通知渠道替换实现。

还要明确边界值：恰好三十秒算不算过期？设备时钟在未来怎么办？
这些不是语法问题，而是契约问题。
一个函数名再漂亮，也不能替代明确的条件。

## 机制四：从源代码到正在运行的程序

刚写下的文字为什么能变成计算？人写的**源代码**需要先按语法读出结构，再交给执行它的系统。可以把这两步想成先把草图整理成规则明确的操作清单，再由负责执行清单的工长安排工作。
**编译**是把一种程序表示转换成另一种表示；**解释执行**是由另一段程序读取某种表示并执行相应操作。

常用 Python 实现 **CPython** 的常规路径是：Python 源代码 → **字节码**（供解释器读取的中间指令）→ 由 CPython 的解释器执行。
解释器中的**虚拟机**是用软件实现的执行机制；它读取字节码，再由自身对应的机器指令完成操作。字节码不等于 CPU 的机器码，也不是必须先把整段字节码另行转换成机器码才能运行。参见 [Python 官方 bytecode 定义](https://docs.python.org/3/glossary.html#term-bytecode)。
**类比边界：** 工长比喻帮助区分表示与执行，不意味着每条源码都恰好对应一条字节码或一条机器指令。

“编译”和“解释”描述的是执行策略，不是两种永远互斥的语言类别。
有些系统提前编译成机器码，有些解释中间表示，也有实现会在运行时再编译；具体组合需要查看实现。
日常排错更应先问：错误发生在解析、启动、运行还是调用外部服务时？

同一个源文件运行两次，会产生两次运行实例。
代码像规则说明，运行实例则还包含当前变量、执行位置和已打开的资源；这个区别会在[操作系统章节](05-operating-systems.md)展开。

## 机制五：抽象与接口让修改范围可控

如果上层只需要“按相机编号读取最新状态”，它不应同时知道数据表结构、缓存布局与网络连接细节。
一个明确的接口可以承诺输入编号、返回状态及更新时间，并说明不存在或超时怎样表示。
下层随后可以改变内部实现，只要仍履行这份契约。

抽象不等于隐藏所有代价。
如果一次调用可能等待五秒、返回旧数据或触发写入，这些行为会影响调用者，就应进入接口约定。
否则，程序表面上被拆成了模块，实际仍靠隐含假设互相牵制。

## 建筑类比：专业接口与内部做法

建筑专业协作会约定轴网、标高、洞口与荷载条件；各专业在这些边界内继续深化。
程序模块也通过接口协调，让内部修改不必传播到每个使用者。
**类比边界：** 程序接口能被机器反复调用，错误会迅速放大；含糊的口头约定通常不能作为稳定的执行契约。

## 最小实验：顺序、分支与重复

现在用刚学的写法处理两条虚构记录。**字典**用键查找对应的值，例如 `record["id"]` 用键 `"id"` 读取编号，空字典写作 `{}`；下面先逐条建立编号索引，只把在线编号加入列表，再做两次倒数。
`for` 每轮取一条记录，`if` 决定是否加入；`while` 每轮先检查能否继续，`remaining -= 1` 就是把当前数减一后重新赋给同一个名字。

先预测留下哪个编号，以及倒数何时结束，再运行：

```python
records = [{"id": "a", "online": True}, {"id": "b", "online": False}]
by_id = {}
online_ids = []
for record in records:
    by_id[record["id"]] = record  # 按编号保存当前记录
    if record["online"]:
        online_ids.append(record["id"])  # 只有在线记录才加入

remaining = 2
while remaining > 0:
    remaining -= 1  # 每轮向结束条件走近一步
print(online_ids, remaining)
```

预期输出：

```text
['a'] 0
```

`by_id["a"]` 可以按编号取到对应记录。如果重复写入同一个键，后写的值会覆盖前一个值；这不等于已经解决事件去重、更新顺序或身份冲突。
`remaining` 从二变一，再从一变零，所以循环会结束；删除这条更新语句将导致无限循环，不必实际运行这个错误版本。

## 进阶延伸（可选）：观察编译与共享对象

<details>
<summary>看见编译产生的代码对象，复核引用共享</summary>

下面把一段固定的教学源代码编译成代码对象，再执行定义。
`compile(...)` 把源码转换成代码对象，`exec(...)` 执行它；`namespace` 是保存定义结果的名字表，这里用字典承载。可以先跳过，不影响读写普通函数。

```python
source = """
def is_stale(last_seen, now, limit=30):
    return now - last_seen > limit
"""
namespace = {}
compiled = compile(source, "camera_rule", "exec")  # 此时还没有调用判断函数
exec(compiled, namespace)  # 执行定义，把函数放入名字表
rule = namespace["is_stale"]

print(type(compiled).__name__)
print(rule(100, 130), rule(100, 131))
cameras = ["cam-01"]
alias = cameras  # 两个名字指向同一个列表
alias.append("cam-02")
print(cameras)
```

预期输出：

```text
code
False True
['cam-01', 'cam-02']
```

`compile` 返回可执行的代码对象，行为见 [Python 内置函数文档](https://docs.python.org/3/library/functions.html#compile)。
最后一行是共享引用的结果；程序没有执行“把 alias 复制回 cameras”这一步。
`dis` 模块还能查看字节码，但它属于实现细节，会随 CPython 版本变化，本实验不依赖具体指令名称。参见 [Python dis 文档](https://docs.python.org/3/library/dis.html)。

## 闭卷检查：先预测，再解释

1. **预测：** 有一个列表 `cameras = ["cam-01", "cam-02"]`，先执行 `alias = cameras`，再执行 `alias = []`，此时打印 `cameras` 会得到什么？
2. **解释：** 为什么函数返回正确，却仍可能让整个系统出现错误？
3. **迁移：** 要把状态来源从本地文件换成远程接口，哪些约定应该保留，哪些代价应该重新说明？

<details>
<summary>答案要点与常见误区</summary>

1. 仍是包含两个编号的原列表；重新绑定 alias 不会改变 cameras 引用的对象。
2. 可能有未预期副作用、错误的单位、过时输入、时间边界误解，或调用者误用了结果。
3. 保留编号含义、输出字段与错误语义；补充网络超时、数据新鲜度、失败重试及调用成本的约束。

常见误区：变量赋值总会复制对象；动态类型等于没有类型；有类型标注就完成了输入校验。
也不要把“解释型”当成“没有编译阶段”，或把“接口能调用”当成“调用契约完整”。

</details>
