# 03｜编程：用抽象组织可执行的规则

> **一句话核心：编程是把需求写成可检查、可组合、可执行的规则。**

语法让机器能够解析文字，抽象让人能够管理规模。
本章不追求记住所有 Python 写法，而是理解一段程序怎样表示数据、组织计算，以及为什么“能运行”还不等于“满足需求”。

## 先修与学习目标

先理解[表示与逻辑](01-computation.md)以及[存储程序](02-hardware.md)。
只需读懂顺序、条件与重复；遇到不熟悉的符号，先问它表达什么关系。
学完应能解释一个函数的输入、输出、副作用、前置条件和失败方式。

## 关键术语：从数据到模块

- **变量（variable）**：程序中用于引用或保存值的机制；具体含义由语言决定。
- **对象（object）**：Python 中承载数据的实体，具有身份、类型和值。
- **类型（type）**：说明值的类别与允许的操作，帮助约束程序行为。
- **函数（function）**：把一段计算封装成可调用单元，接收参数并返回结果。
- **作用域（scope）**：一个名字可以被查找和使用的程序区域。
- **副作用（side effect）**：除返回值外，对共享数据、文件、网络等造成的变化。
- **编译（compilation）**：把一种程序表示转换成另一种表示。
- **解释执行（interpretation）**：由另一段程序读取并执行某种程序表示。
- **接口与契约（interface / contract）**：约定如何调用，以及输入、输出和错误必须满足什么条件。

## 机制一：变量不是万能的“盒子”

“变量是盒子”能帮助初学者起步，但在 Python 中，更准确的说法是名字绑定到对象。
执行 `a = []` 创建列表并绑定名字；执行 `b = a` 后，两个名字引用同一个列表，不会自动复制一份。
名字绑定见 [Python 执行模型](https://docs.python.org/3/reference/executionmodel.html)。

因此，通过 `b.append(...)` 修改列表，也会从 `a` 观察到变化。
但若随后执行 `b = []`，只是让 `b` 指向另一个列表，不会清空原来的列表。
区分“改变对象”与“改变引用”，才能理解共享数据和许多难找的修改问题。

整数、字符串等对象不可变，列表、字典通常可变；这里讨论的是对象的行为，而不是变量名能否再次赋值。
详见 [Python 数据模型 §3.1](https://docs.python.org/3/reference/datamodel.html)。
也不要把 Python 的规则机械套给所有语言；有的语言更强调固定类型的存储位置和值复制。

## 机制二：类型约束操作，但业务含义还要表达

数值 `3` 与文本 `"3"` 看起来相近，却支持不同操作：两个数字相加得到六，两个字符串拼接得到“33”。
程序必须在接收外部数据时决定是否转换，以及转换失败怎样处理。
类型系统帮助排除某些错误，却无法自动知道“三米”被误当成“三毫米”。

Python 的类型属于对象，很多检查发生在运行时。
类型标注可以帮助阅读和静态检查，但标注本身不会在调用时自动验证输入，见 [Python typing 说明](https://docs.python.org/3/library/typing.html)。
所以，面向相机治理的接口仍要明确：时间戳用秒还是毫秒，空值是否允许，编号能否重复。

这种约束就像尺寸标注：只有数字，没有单位和适用范围，图纸仍然不完整。
类型不是越复杂越好，而是应让常见误用更难发生，让错误更早被发现。

## 机制三：函数是可组合的计算边界

考虑“超过三十秒没有心跳就认为过期”。
把 `last_seen`、`now` 和 `limit` 作为参数，函数只返回判断结果，就能在不同设备和不同时间上复用。
若函数偷偷读取当前时间、直接发送告警并修改数据库，调用者就更难独立预测它的结果。

这不是说副作用不好；系统最终总要读取设备、保存数据、执行动作。
有用的做法是让判断规则和外部动作拥有清晰边界：先计算“应当告警吗”，再决定如何发送、记录和重试。
这样既容易用固定输入检查规则，也容易为不同通知渠道替换实现。

还要明确边界值：恰好三十秒算不算过期？设备时钟在未来怎么办？
这些不是语法问题，而是契约问题。
一个函数名再漂亮，也不能替代明确的条件。

## 机制四：从源代码到正在运行的程序

人写的源代码需要经过解析，建立结构，检查规则，再形成可执行的表示。
常见的提前编译路径会生成机器码并进行链接；程序启动时，操作系统再安排地址空间、加载内容和执行资源。
不同语言与实现可能采用不同阶段，不能把这条路径当成唯一模板。

CPython 会把 Python 代码编译成字节码，再由解释器执行；因此“Python 完全不编译”是错误说法。
其 `dis` 模块能查看字节码，同时官方明确说明字节码是实现细节，会随版本变化。
参见 [Python dis 文档](https://docs.python.org/3/library/dis.html)。

“编译”和“解释”描述的是执行策略，不是两种永远互斥的语言类别。
系统可以提前编译、解释中间表示，也可以在运行时再编译；具体组合需要查看实现。
日常排错更应先问：错误发生在解析、启动、运行还是调用外部服务时？

同一个源文件运行两次，会产生两次运行实例。
代码像规则说明，运行实例则还包含当前变量、执行位置和已打开的资源；这个区别会在[操作系统章节](05-operating-systems.md)展开。

## 机制五：抽象与接口让修改范围可控

如果上层只需要“按相机编号读取最新状态”，它不应同时知道数据表结构、缓存布局与网络连接细节。
一个明确的接口可以承诺输入编号、返回状态及更新时间，并说明不存在或超时怎样表示。
下层随后可以改变内部实现，只要仍履行这份契约。

抽象不等于隐藏所有代价。
如果一次调用可能等待五秒、返回旧数据或触发写入，这些行为会影响调用者，就应进入接口约定。
否则，程序表面上被拆成了模块，实际仍靠隐含假设互相牵制。

## 建筑类比：专业接口与内部做法

建筑专业协作会约定轴网、标高、洞口与荷载条件；各专业在这些边界内继续深化。
程序模块也通过接口协调，让内部修改不必传播到每个使用者。
**类比边界：**程序接口能被机器反复调用，错误会迅速放大；含糊的口头约定通常不能作为稳定的执行契约。

## 最小实验：编译、调用与共享对象

下面把一段固定的教学源代码编译成代码对象，再执行定义。
这里不依赖任何特定版本的字节码指令名称。

```python
source = """
def is_stale(last_seen, now, limit=30):
    return now - last_seen > limit
"""
namespace = {}
compiled = compile(source, "camera_rule", "exec")
exec(compiled, namespace)
rule = namespace["is_stale"]

print(type(compiled).__name__)
print(rule(100, 130), rule(100, 131))
cameras = ["cam-01"]
alias = cameras
alias.append("cam-02")
print(cameras)
```

预期输出：

```text
code
False True
['cam-01', 'cam-02']
```

`compile` 返回可执行的代码对象，行为见 [Python 内置函数文档](https://docs.python.org/3/library/functions.html#compile)。
最后一行是共享引用的结果；程序没有执行“把 alias 复制回 cameras”这一步。

## 语法桥梁：读懂下一章需要的四种结构

列表 `[]` 按顺序保存多条记录；字典 `{}` 用键查找对应的值。
`for` 逐个处理集合中的元素，`if` 只执行满足条件的分支，`while` 则在条件成立时重复。
缩进决定哪些语句属于同一个代码块；`=` 赋值，`==` 比较是否相等。

先预测下面留下哪个编号，以及循环何时结束，再运行：

```python
records = [{"id": "a", "online": True}, {"id": "b", "online": False}]
by_id = {}
online_ids = []
for record in records:
    by_id[record["id"]] = record
    if record["online"]:
        online_ids.append(record["id"])

remaining = 2
while remaining > 0:
    remaining -= 1
print(online_ids, remaining)
```

预期输出：

```text
['a'] 0
```

`by_id["a"]` 可以按编号取到对应记录。如果重复写入同一个键，后写的值会覆盖前一个值；这不等于已经解决事件去重、更新顺序或身份冲突。
`remaining` 每轮减一，所以循环会结束；删除这条更新语句将导致无限循环，不必实际运行这个错误版本。
进一步语法见 [Python 控制流教程](https://docs.python.org/3/tutorial/controlflow.html)与[数据结构教程](https://docs.python.org/3/tutorial/datastructures.html)。

## 闭卷检查：先预测，再解释

1. **预测：**例子最后再执行 `alias = []`，此时打印 `cameras` 会得到什么？
2. **解释：**为什么函数返回正确，却仍可能让整个系统出现错误？
3. **迁移：**要把状态来源从本地文件换成远程接口，哪些约定应该保留，哪些代价应该重新说明？

<details>
<summary>答案要点与常见误区</summary>

1. 仍是包含两个编号的原列表；重新绑定 alias 不会改变 cameras 引用的对象。
2. 可能有未预期副作用、错误的单位、过时输入、时间边界误解，或调用者误用了结果。
3. 保留编号含义、输出字段与错误语义；补充网络超时、数据新鲜度、失败重试及调用成本的约束。

常见误区：变量赋值总会复制对象；动态类型等于没有类型；有类型标注就完成了输入校验。
也不要把“解释型”当成“没有编译阶段”，或把“接口能调用”当成“调用契约完整”。

</details>
