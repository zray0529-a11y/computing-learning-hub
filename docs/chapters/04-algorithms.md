# 04｜算法与数据结构：把正确性和代价一起设计

> **一句话核心：算法决定做哪些步骤，数据结构决定这些步骤需要付出多少代价。**

从一万台相机中找一台、检查重复记录、寻找道路之间的连接，都可以写成程序。
但“结果看起来正确”和“数据增加后仍能工作”是不同要求。
本章建立一种习惯：先定义问题，再选择表示，说明正确性，最后分析时间与空间。

## 先修与学习目标

先读[编程与抽象](03-programming.md)，理解列表、字典、循环和函数。
只需会比较数量级；看到对数时，把它理解成“不断减半需要多少次”即可。
目标是能给每个性能结论补上输入规模、操作模型和适用条件。

## 关键术语：从问题到代价

- **数据结构（data structure）**：存放数据并支持一组操作的组织方式。
- **数组（array）**：通过下标访问元素的顺序存储；便于定位，不代表任意插入都便宜。
- **栈与队列（stack / queue）**：分别按后进先出、先进先出的规则取元素。
- **映射与集合（map / set）**：分别表达键到值的对应、元素是否存在。
- **复杂度（complexity）**：资源消耗如何随输入规模增长，不直接等于实测秒数。
- **哈希（hashing）**：把键映射到有限范围，帮助定位候选位置。
- **图（graph）**：用节点和边描述关系，可表达道路、依赖和数据流。
- **不变式（invariant）**：在某个执行阶段始终成立的性质，用于论证正确性。
- **广度优先搜索（BFS）**：按离起点的边数逐层探索图的方法。

## 机制一：先说明要支持什么操作

相机清单若主要按顺序导出，顺序存储很自然；若反复按编号查找，可以建立编号到记录的映射。
若要处理待分析视频，队列可以表达先到先处理；若要沿模型层级探索，栈可以保存尚未处理的分支。
没有对所有操作都最优的数据结构。

数组按下标定位通常方便，但在中间插入时，常要移动后续元素。
链式结构连接分散的节点；已知插入位置时可以调整连接，但找到第几个节点往往仍需逐个走过去。
因此，“插入很快”必须说明是否已经找到位置。
[MIT 数据结构讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/79a07dc1cb47d76dae2ffedc701e3d2b_MIT6_006S20_lec2.pdf)区分了操作接口与具体表示。

还要定义“重复”：编号相同、位置相同、图像相同，是不同问题。
算法能严格执行相等判断，却不会替你决定业务上的同一性。

## 机制二：复杂度看增长，不是假装测过速度

若检查每台相机一次，工作量随设备数 n 近似线性增长。
若把每台与其他每台比较，候选配对数量可能达到 n(n−1)/2，增长接近平方。
从一千台扩到一万台，前者约多十倍工作，后者约多一百倍工作。

大 O 表示渐近上界，会忽略常数与较低阶项。
它本身不自动表示“最坏情况”；分析者必须说明讨论的是最坏、平均、期望还是摊销代价。
基本定义见 [MIT 算法导论讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/477c78e0af2df61fa205bcc6cb613ceb_MIT6_006S20_lec1.pdf)。

增长趋势也不能取代测量：一个固定开销很大的算法，在小数据上可能更慢。
而把“比较一次”视为常数成本，也隐含键长度受控等条件；比较长视频内容当然不是一次廉价操作。
实际系统还要考虑内存占用、数据拷贝和缓存行为。

## 机制三：排序为什么能帮助查找

如果编号已经有序，查看中间元素后，就能排除不可能包含目标的一半。
重复这一过程，候选范围从 n 变成 n/2、n/4，最终缩到一个，比较次数为对数级。
但这要求顺序成立，并能有效访问中间位置；未排序列表不能直接获得二分查找的正确性。

排序也有成本。若只查一次，先排序可能比直接扫描更费事。
若同一批数据会被查询很多次，排序或建立索引的前期投入可能值得。
数据不断变化时，还需要计算维护顺序和索引的成本。

理解一种排序思路即可：归并排序先把数据反复分成两半，再合并已经有序的两段。
合并时每次取两边较小的首项；每一层处理约 n 个元素，层数约为 log₂n。
因此常见实现的时间为 O(n log n)，同时要付出额外缓冲空间。

## 机制四：哈希让候选范围变小，但不能消除碰撞

假设用 `编号 % 4` 选择四个桶，编号 1 和 5 都进入桶 1。
这就是碰撞：不同键得到了相同的定位结果。
如果键的可能数量大于桶数，就不可能给每个键永久分配一个独占桶。

哈希表必须处理碰撞，例如在桶中保留多条记录，或者继续探查其他位置。
查找时仍需比较实际键，不能把“哈希相同”直接当成“对象相同”。
机制见 [MIT 哈希讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/ce9e94705b914598ce78a00a70a1f734_MIT6_006S20_lec4.pdf)。

分布较均匀、容量与元素数量适当匹配、键操作成本受控时，常见哈希表能获得期望常数级查找。
但最坏情况、扩容以及计算长键的哈希都需要单独分析。
相机编号映射适合精确查找，却不会自动支持“经度在某个范围内”的高效检索。

## 机制五：图把关系变成可以搜索的对象

把路口当节点、道路当边，就得到一张图；把处理步骤当节点、先后依赖当边，也能得到图。
有向边表达方向，无向边表达双向关系，边权可以表示距离或耗时。
图不是一种固定画法，而是一种关系模型。

BFS 使用队列：先访问起点，再访问一步可达的点，再访问两步可达的点。
它把首次发现的节点标记为已访问，避免在环中无限重复。
当每条边成本相同时，首次到达的层数就是最少边数；在邻接表表示下，常见实现时间为 O(V+E)。
依据见 [MIT BFS 讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/196a95604877d326c6586e60477b59d4_MIT6_006S20_lec9.pdf)。

如果一条路耗时一分钟，另一条耗时十分钟，最少经过几条路未必最快到达。
这时需要处理权重的算法；改变问题定义，也就改变了正确性要求。

## 建筑类比：目录、索引与连接关系

图纸按编号排放，利于顺序定位；建立“构件编号→图纸页”的索引，利于直接查询。
而查“哪些设备经过这段管线连接”，要保留连接图，单有清单并不够。
**类比边界：**算法只看到你提供的关系；现场可通行但模型未录入的门，不会被搜索自动发现。

## 最小实验：找到最少连接次数

例子把五个区域看成无向图，每条连接成本都记为一步。

```python
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "E"],
    "D": ["B", "E"],
    "E": ["C", "D"],
}
distance = {"A": 0}
queue = deque(["A"])
while queue:
    current = queue.popleft()
    for neighbor in graph[current]:
        if neighbor not in distance:
            distance[neighbor] = distance[current] + 1
            queue.append(neighbor)
print(sorted(distance.items()))
print(distance["E"])
```

预期输出：

```text
[('A', 0), ('B', 1), ('C', 1), ('D', 2), ('E', 2)]
2
```

可以跟踪一个不变式：队列按距离层次处理，已发现节点不会重复入队。
这解释了为何环不会导致无限搜索，也解释了首次发现距离的意义；测试输出只是对该推理的一次检查。

## 闭卷检查：先预测，再解释

1. **预测：**在图中增加 A 与 E 的直接连接，E 的距离变成多少？哪些假设保持不变？
2. **解释：**为什么“哈希查找是 O(1)”和“可能发生碰撞”并不矛盾？
3. **迁移：**现在要找城市里耗时最短的路线，为什么不能直接把本例的结果称作最快路线？

<details>
<summary>答案要点与常见误区</summary>

1. 变为一步；仍假设图关系已正确录入、每条边成本相同，且从 A 出发。
2. 碰撞可被处理；在明确的分布和负载等条件下，期望候选数量仍可保持常数级，但不能据此保证每次操作都是常数时间。
3. 本例优化的是边数；真实道路耗时有权重，还可能随时间变化，必须重新定义目标与输入。

常见误区：用大 O 代替基准测试；把二分查找用于无序数据；把一个样例通过当成一般性证明。
正确性需要说明前置条件、保持的性质以及停止后为何满足目标。
