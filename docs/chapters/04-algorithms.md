# 04｜算法与数据结构：把正确性和代价一起设计

> **一句话核心：算法决定做哪些步骤，数据结构决定这些步骤需要付出多少代价。**

图解要在已经升序排列的 `[2, 5, 8, 13, 21, 34, 55]` 中找到 `21`。先与中间的 `13` 比较，保留右侧三项；再与 `34` 比较，保留左侧的 `21`，最后确认它位于下标 `4`（下标从零开始）。
为什么敢排除其他数，又为什么三次比较就够了？本章用这个例子把“不会漏掉目标”与“做了多少工作”连起来，再扩展到相机编号索引和区域连接搜索。

## 先修与学习目标

先读[编程与抽象](03-programming.md)，理解列表、字典、循环和函数。
只需会比较数量级；看到对数时，把它理解成“不断减半需要多少次”即可。
目标是能给每个性能结论补上输入规模、操作模型和适用条件。

## 关键术语：从问题到代价

- **数据结构（data structure）**：存放数据并支持一组操作的组织方式。
- **数组（array）**：通过下标访问元素的顺序存储；便于定位，不代表任意插入都便宜。
- **栈与队列（stack / queue）**：分别按后进先出、先进先出的规则取元素。
- **映射与集合（map / set）**：分别表达键到值的对应、元素是否存在。
- **复杂度（complexity）**：资源消耗如何随输入规模增长，不直接等于实测秒数。
- **哈希（hashing）**：把键映射到有限范围，帮助定位候选位置。
- **图（graph）**：用节点和边描述关系，可表达道路、依赖和数据流。
- **不变式（invariant）**：约定在每轮某个检查点都成立的“底线规矩”，例如“目标若存在，就仍在保留范围内”。
- **广度优先搜索（BFS）**：按离起点的边数逐层探索图的方法。

## 机制一：先说明要支持什么操作

如果每天要按编号找同一批图纸，从头翻起会重复花时间；按号排好、加目录，或者保存连接关系，解决的是不同问题。
相机清单若主要按顺序导出，顺序存储很自然；若反复按编号查找，可以建立编号到记录的映射。
若要处理待分析视频，队列可以表达先到先处理；若要沿模型层级探索，栈可以保存尚未处理的分支。
没有对所有操作都最优的数据结构。

数组按下标定位通常方便，但在中间插入时，常要移动后续元素。
链式结构连接分散的节点；已知插入位置时可以调整连接，但找到第几个节点往往仍需逐个走过去。
因此，“插入很快”必须说明是否已经找到位置。
[MIT 数据结构讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/79a07dc1cb47d76dae2ffedc701e3d2b_MIT6_006S20_lec2.pdf)区分了操作接口与具体表示。

还要定义“重复”：编号相同、位置相同、图像相同，是不同问题。
算法能严格执行相等判断，却不会替你决定业务上的同一性。

## 机制二：复杂度看增长，不是假装测过速度

假设要在一千条编号中找一个目标，先不问电脑用了几毫秒，先数“最多要查看多少个编号”。如果从头逐项找，目标在末尾或不存在时，要看完一千项；若数据已经有序，就能像查按词序排好的字典一样，反复翻到剩余范围的中间。
**输入规模 `n`** 在这里就是编号个数。暂时约定访问一个位置、比较两个短编号都算一次固定成本操作，才能把步骤数与输入大小联系起来。

| 方法与前提 | `n = 1,000` 时数什么 | `n = 10,000` 时怎样变化 | 常用增长记号 |
|---|---|---|---|
| 顺序查找，最坏情形 | 查看 1,000 项 | 查看 10,000 项，增至十倍 | `O(n)`，线性级 |
| 已有序且能直接访问中间项，二分查找 | 最多查看 10 个中间项 | 最多查看 14 个中间项 | `O(log n)`，对数级 |
| 每两项配成一对，不与自身比较、不重复配对 | 比较 499,500 对 | 比较 49,995,000 对，约增至百倍 | `O(n²)`，平方级 |

二分查找的“对数”不用先背公式：一千个候选，每轮保留至多约一半，范围很快就小到零或一项。若规模翻倍，只会多约一轮；`log₂ n` 就是在数这种减半的轮数。
配对为什么接近平方？第一项与后面 `n−1` 项比较，第二项只与后面 `n−2` 项比较，直到最后；总数是 `n(n−1)/2`。这里在数操作，不是在报告性能实测。

**大 O** 描述输入规模足够大时，工作量增长的一个上界，并忽略固定倍数和影响较小的项；表中列的是这些方法常用的增长界。
它本身不自动表示“最坏情况”：上表特意说明前两行按最坏输入计数；后面哈希表的期望代价则还依赖分布等假设。平均、期望与摊销的区别放在文末可选框。
基本定义见 [MIT 算法导论讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/477c78e0af2df61fa205bcc6cb613ceb_MIT6_006S20_lec1.pdf)。

增长趋势也不能取代测量：一个固定开销很大的算法，在小数据上可能更慢。
而把“比较一次”视为常数成本，也隐含键长度受控等条件；比较长视频内容当然不是一次廉价操作。
实际系统还要考虑内存占用、数据拷贝和缓存行为。

## 机制三：排序为什么能帮助查找

按图解逐轮看，不要只记住“砍掉一半”：

| 本轮保留的值 | 查看中间值 | 能确定什么 |
|---|---|---|
| `2, 5, 8, 13, 21, 34, 55` | `13` | `21 > 13`；有序性保证 `13` 及左侧所有值都太小，保留 `21, 34, 55` |
| `21, 34, 55` | `34` | `21 < 34`；`34` 及右侧所有值都太大，只保留 `21` |
| `21` | `21` | 与目标相等，返回它在原数组中的下标 `4` |

每次排除之前，都有“这一侧不可能是目标”的理由。这就形成一条可以检查的**循环不变式**：**每轮开始时，目标如果存在，一定还在保留的左右边界之间。**
一开始边界包含整个数组，这句话成立；每轮只删掉确定不可能的部分，因此下一轮仍成立；如果最终范围为空，就能说明目标不存在。再加上未找到目标的每一轮都会缩小范围，找到时立即返回，才有“会结束且结论正确”的完整理由。
这是推理规则，不是给某个变量起了“不变式”的名字，也不是只看一次输出就算证明。

二分查找要求顺序成立，并能有效访问中间位置。无序清单中的左侧可能还藏着更大的数，照样排除会漏掉目标；按顺序排列却只能逐个走过去的结构，也不一定具有对数级总耗时。

排序也有成本。若只查一次，先排序可能比直接扫描更费事。
若同一批数据会被查询很多次，排序或建立索引的前期投入可能值得。
数据不断变化时，还需要计算维护顺序和索引的成本。

要看懂排序的代价，可以先想象两摞分别已经按编号排好的图纸。每次比较两摞最上面一张，取走较小的那张，就能合成一摞有序图纸，不必把每张与所有其他图纸比较。
**归并排序**先把数据反复分成两半，直到各段足够小，再按这个规则逐层合并。每一层合计处理约 `n` 项，层数约为 `log₂ n`，两者相乘才得到常见数组实现的 `O(n log n)` 时间；这类实现还需要额外的临时存放空间。
二分查找与归并排序的分析见 [MIT 排序讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/6d1ae5278d02bbecb5c4428928b24194_MIT6_006S20_lec3.pdf)。

## 机制四：哈希让候选范围变小，但不能消除碰撞

如果总按编号精确查找，我们希望先算出“去哪格找”，减少从头翻清单的工作。把四个抽屉编号为 `0、1、2、3`，约定用“编号除以四的余数”决定先放哪个抽屉；代码中取余数写作 `%`。
这个教学哈希规则是 `编号 % 4`：编号 `1` 除以四余一，编号 `5` 除以四也余一，所以它们都进入桶 `1`；“桶”就是这类候选存放位置。
这就是**碰撞**：不同键得到了相同的定位结果。它可以正常发生，不表示编号相同或设备是同一台。
如果键的可能数量大于桶数，就不可能给每个键永久分配一个独占桶。

哈希表必须处理碰撞，例如在桶中保留多条记录，或者按约定继续查其他位置。若桶 `1` 里存着编号 `1` 和 `5`，找 `5` 时还要逐个核对实际编号，不能取出第一条就算找到。
因此，“哈希相同”不能直接当成“对象相同”。这个四桶模型只解释机制，不是 Python 字典内部实现的完整复刻。
机制见 [MIT 哈希讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/ce9e94705b914598ce78a00a70a1f734_MIT6_006S20_lec4.pdf)。

分布较均匀、桶的数量随元素数量适当增长、键操作成本受控时，平均每桶的候选数量可以保持有界，常见哈希表因此能获得**期望 `O(1)` 查找**：随记录总量增长，预期工作量不必同比增加，而不是承诺每次恰好做一步。
但最坏情况、扩容以及计算长键的哈希都需要单独分析。
只按首字母把图纸分成固定几组，组内仍可能越来越长；这种目录类比本身不能证明 `O(1)`。同样，始终只用四个桶装无限增长的数据，也不满足上述容量条件。
相机编号映射适合精确查找，却不会自动支持“经度在某个范围内”的高效检索。

## 机制五：图把关系变成可以搜索的对象

要回答“从 A 区域经过几次连接能到 E”，仅保存区域编号还不够，还要记录哪些区域相连。像看道路连接图一样，把路口当**节点**、道路当**边**，就得到一张图；把处理步骤当节点、先后依赖当边，也能得到图。
有向边表达方向，无向边表达双向关系，边权可以表示距离或耗时。
图不是一种固定画法，而是一种关系模型。

**广度优先搜索（BFS）**使用先到先处理的队列：先访问起点，再访问一步可达的点，再访问两步可达的点。
它把首次发现的节点标记为已访问，避免在环中无限重复。
当每条边成本相同时，首次到达的层数就是最少边数。
把每个节点相连的邻居单独列出来，这种表示叫**邻接表**。若总共有 `V` 个节点、`E` 条边，节点各处理一次，邻居清单中的连接各检查一次；无向边会从两端各看到一次，但只多一个固定倍数，因此常见实现的增长界为 `O(V+E)`。
这个结论假设队列操作和记录“是否已发现”可按常数成本处理；本章 Python 字典的对应分析采用期望常数成本。只从一个起点出发时，实际探索的是它能到达的部分。
依据见 [MIT BFS 讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/196a95604877d326c6586e60477b59d4_MIT6_006S20_lec9.pdf)。

如果一条路耗时一分钟，另一条耗时十分钟，最少经过几条路未必最快到达。
这时需要处理权重的算法；改变问题定义，也就改变了正确性要求。

## 建筑类比：目录、索引与连接关系

图纸按编号排放，利于顺序定位；建立“构件编号→图纸页”的索引，利于直接查询。
而查“哪些设备经过这段管线连接”，要保留连接图，单有清单并不够。
**类比边界：**算法只看到你提供的关系；现场可通行但模型未录入的门，不会被搜索自动发现。

## 最小实验：找到最少连接次数

例子把五个区域看成无向图，每条连接成本都记为一步。先手算：从 A 一步能到 B、C；下一层才能到 D、E，所以 E 的最少连接次数应为二。
代码中的 `distance` 同时记住“已经发现谁”和“从 A 至少要走几步”。`deque` 是标准库提供的双端队列；这里在末尾添加、从开头取出，正好实现先到先处理。

```python
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "E"],
    "D": ["B", "E"],
    "E": ["C", "D"],
}
distance = {"A": 0}
queue = deque(["A"])
while queue:
    current = queue.popleft()  # 先处理最早进入队列的区域
    for neighbor in graph[current]:
        if neighbor not in distance:  # 首次发现时就记下，避免重复入队
            distance[neighbor] = distance[current] + 1
            queue.append(neighbor)
print(sorted(distance.items()))
print(distance["E"])
```

预期输出：

```text
[('A', 0), ('B', 1), ('C', 1), ('D', 2), ('E', 2)]
2
```

可以跟踪另一条“底线规矩”：每轮开始时，队列中的节点按非递减距离排列，已发现节点不会重复入队。
如果某节点还有一条更短的路线，那条路线的前一个节点就会在更早的一层被处理，目标应当已经被发现。因此首次发现得到的就是最少边数，而不重复入队保证环不会导致无限搜索；测试输出只是对该推理的一次检查。

## 闭卷检查：先预测，再解释

1. **预测：**在图中增加 A 与 E 的直接连接，E 的距离变成多少？哪些假设保持不变？
2. **解释：**为什么“哈希查找是 O(1)”和“可能发生碰撞”并不矛盾？
3. **迁移：**现在要找城市里耗时最短的路线，为什么不能直接把本例的结果称作最快路线？

<details>
<summary>答案要点与常见误区</summary>

1. 变为一步；仍假设图关系已正确录入、每条边成本相同，且从 A 出发。
2. 碰撞可被处理；在明确的分布和负载等条件下，期望候选数量仍可保持常数级，但不能据此保证每次操作都是常数时间。
3. 本例优化的是边数；真实道路耗时有权重，还可能随时间变化，必须重新定义目标与输入。

常见误区：用大 O 代替基准测试；把二分查找用于无序数据；把一个样例通过当成一般性证明。
正确性需要说明前置条件、保持的性质以及停止后为何满足目标。

## 进阶延伸（可选）：分析的到底是哪种代价？

<details>
<summary>最坏、平均、期望与摊销分别回答什么</summary>

- **最坏代价：**固定规模下，选择最费工作的合法输入，例如顺序查找的目标不存在。
- **平均代价：**先说明输入出现的概率，再计算平均需要多少工作；不声明概率就不能随口称为“平均”。
- **期望代价：**对指定的随机过程或分布取平均，例如随机选择哈希函数时的预期查找成本；它不保证每一次都同样快。
- **摊销代价：**把一串操作的总成本分摊到每次操作。动态数组追加时，偶尔要扩容并搬移旧数据，某一次会很贵；若按合适比例扩容，把搬移成本分摊到此前许多次追加，可以得到每次追加的常数级摊销成本。这里不需要假定输入随机，也不保证单次最坏延迟很低。

因此，看到 `O(1)` 还应继续问“哪一种代价、键多长、容量怎样调整”。动态数组与摊销分析见 [MIT 数据结构讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/79a07dc1cb47d76dae2ffedc701e3d2b_MIT6_006S20_lec2.pdf)。

</details>
