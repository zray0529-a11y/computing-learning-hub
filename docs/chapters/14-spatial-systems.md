# 14 空间与数字孪生：连接位置、外观、语义和实时状态

图解中的东门在局部米制坐标 `(3, 4)`，距原点直线 5 米；这还不能说明隔着围墙能否走到。它的实体标识是 `gate-east`，一条“人少”观察在 10:12 采集、10:14 入库；10:25 查看时已经过去 13 分钟，超过示例的 10 分钟有效期，所以当前状态应显示“未知”。本章逐层解释这几条信息为什么不能互相替代。

## 核心判断

位置、三维外观、实体身份与实时状态是四类不同信息。把场景渲染得逼真，不会自动得到正确的语义（对象是什么、与谁有什么关系）、可行走路线、当前人流或物理仿真。

先修：[图与算法](04-algorithms.md)、[数据库](07-databases.md)、[数学与ML](10-math-and-ml.md)。本章通过通用的城市、建筑与景区场景，练习基础知识在空间系统中的应用。

## 把系统拆成能分别验证的层

| 层 | 主要问题 | 典型数据与检查 |
|---|---|---|
| 空间参考 | 对象到底在哪里 | 坐标系、单位、控制点误差 |
| 几何与外观 | 对象长什么样 | 用点、表面、照片等表示，下文逐一比较 |
| 实体与关系 | 对象是谁、与谁有关 | 稳定ID、入口关系、道路拓扑（路段的连接结构） |
| 时间与状态 | 何时观察到什么 | 采集时间、有效期、来源和证据 |
| 交互与决策 | 用户需要怎样的回答或动作 | 查询条件、权限、可解释结果 |

以景区入口为例：模型里有一个门洞，不等于系统已经知道它是可开放的入口；知道名称，不等于知道今天开放；有三分钟前的观察，也不等于知道下一小时的排队时间。

## 坐标先问四件事

坐标属于哪个参考系？各轴如何定义？单位是什么？高度参照是什么？这些没有说明时，两组看起来相近的数不能直接拼接。

GeoJSON 是一种交换地理要素的 JSON 数据格式。它使用WGS84地理坐标和十进制度；位置的前两个元素是经度、纬度。投影坐标或建筑局部坐标可能以米为单位，转换需要明确映射。[RFC 7946](https://www.rfc-editor.org/rfc/rfc7946)

“两个点差0.001”不是一个完整的距离结论。若是度，距离还与位置、方向和测量模型有关；若是米，则含义完全不同。PostGIS 是数据库的空间数据扩展；它的 `ST_DWithin` 用于判断对象是否相距某个距离以内，在 `geometry`（平面几何）类型中按坐标参考系单位解释距离，在 `geography`（地球表面地理对象）类型中用米。[官方定义](https://postgis.net/docs/ST_DWithin.html)

建筑类比是总图坐标与单体局部坐标：每张图单独正确仍可能套合失败。边界是地球曲率、投影、不同高度基准及传感器标定会引入额外误差，不能只靠平移视觉对齐。

## 空间关系与图关系

找附近入口时，不必从整座城市的全部对象开始逐一比较。空间索引把数据按位置组织起来，像先按街区找图纸，再查街区内的对象，可以减少待检查的候选。但“距离近”不代表“归属于”：同一位置可能有多楼层、多个商铺、不同出入口。实体去重需要身份线索和匹配规则，不能只比较名称或坐标。

图中的节点和边表达关系：入口连接哪条路、路径是否可通行、观察支持哪个实体。父子包含关系、道路连通关系、相机观察关系应明确区分，不能混成一条没有语义的“相关”。

路线搜索需要可通行的拓扑和代价；欧氏距离最近不一定步行最快，隔着围墙、水体或楼层时尤其如此。代价还可能随封闭、坡度、拥挤和无障碍需求变化。

## 最小演算：局部米制坐标的距离

```python
from math import hypot

user = (0, 0)
gates = {'east': (3, 4), 'west': (0, 8)}
# hypot(dx, dy) 计算直角三角形的斜边，只得到平面直线距离。
distances = {name: hypot(x-user[0], y-user[1]) for name, (x, y) in gates.items()}
print(distances)
print(min(distances, key=distances.get))
```

确切预期输出：

```text
{'east': 5.0, 'west': 8.0}
east
```

假如东门被围墙隔开，这段代码仍会选它，因为代码没有道路图和通行状态。它只证明一个几何计算，不证明推荐可行。

## 同一扇门，为什么会有不同的三维表示

扫描人员想保留测到的点，渲染人员想显示表面，运维人员想查门的编号和状态。任务不同，需要保留的信息也不同。下面的类比只帮助理解组织方式，不能拿外观相似代替数据检查。

| 表示 | 直观理解与准确含义 | 适合检查什么 | 不能自动得到什么 |
| --- | --- | --- | --- |
| 点云（Point Cloud） | 像撒在表面的细沙；每个点是一次或经处理得到的空间采样，可附颜色等值 | 已采样处的位置、扫描覆盖与配准 | 点之间的连续表面、遮挡背面和构件身份 |
| 表面网格（Mesh） | 像由小面片拼成的外皮；顶点与面明确连接，常用三角形 | 表面形状、渲染；满足额外条件时做碰撞或几何计算 | 网格是否封闭、尺度是否准确、哪一片是可通行的门 |
| 体素（Voxel） | 像把空间分成小积木格；格子可记录占用或某种数值 | 按空间单元统计、检查占用或保存体积场 | 比格子更细的几何细节；“被采样到”也不等于内部已填满 |
| BIM（建筑信息模型） | 像带编号和关联台账的工程构件；把对象、几何、属性和关系组织在一起 | 门的类型、属性、所属楼层及交付数据 | 现场已建成的真实性、实时开放状态或必填数据完整性 |
| 3D Gaussian Splatting（3DGS） | 像许多有颜色的柔软椭球斑叠成画面；用三维高斯参数表示场景并投影渲染 | 从不同视角重现外观 | 可直接使用的封闭表面、工程构件语义或可通行道路图 |

这些名称不处在同一抽象层：点云、表面网格和体素是几何组织方式；BIM 是更广的工程信息模型，其中的几何可以采用网格等表示；3DGS 是用于视图重建与渲染的场景表示方法。因此它们可以组合使用，不能只排成“谁更高级”的替换顺序。几何表示与体素化定义可对照 [Open3D 官方教程](https://www.open3d.org/docs/release/tutorial/geometry/voxelization.html)，BIM/IFC 的对象与关系见 [BIM 专题](../../architecture/01-bim-and-data.md)。

照片或影像则主要记录一个视角的外观。原始3DGS工作以多视图图像、相机标定得到的参数和稀疏三维点为起点，优化高斯的空间分布与外观来合成新视角。[作者项目页](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)

据此做工程推论：逼真渲染质量与测量精度、碰撞体、语义对象、可导航性需要分别验收。一个3DGS场景不会自动提供“哪扇门可进入”的结构；这类能力要另外建立或验证。

单张俯视影像通常不足以唯一确定遮挡立面和背面的真实几何。生成式补全可以形成视觉假设，但不能当作已采集的现场证据。这是观测信息不足的约束，不是换一个渲染引擎就能消除。

大范围场景常通过分块和不同细节层级控制加载与渲染成本。数据传输、解码、内存和GPU绘制都可能成为瓶颈；性能必须说明设备、分辨率、视角与数据规模，不能照搬论文帧率。

## 静态底图与实时证据怎样连接

像把门的构件台账与每次巡检单分开保存：门的身份应能持续关联，而观察会不断增加。可以给开篇的虚构记录这样命名：

| 字段 | 本例的意思 |
| --- | --- |
| `entity_id` | `gate-east`，观察所描述的实体 |
| `observed_at` / `received_at` | 10:12 采集 / 10:14 入库，两种时间分别保存 |
| `state` | 此次观察到的“人少”，不是永久属性 |
| `source_id` / `evidence_id` | 观察来自哪里、可回查哪份证据 |

观察记录追加保存；当前状态是根据这些记录及有效期规则计算出的视图。10:25 时已经距采集时间 13 分钟，即使这是最后入库的一条记录，也不能继续称作“当前人少”。

如果相机转向，旧观察关系未必继续成立；如果某个入口没有可用观察，不能把另一处的状态自动搬过来。来源之间冲突时，应保留分歧与时间，不把模型的自然语言总结作为新的权威事实。

一次C端回答可以分为：观察到的状态及时间、证据覆盖范围、基于状态的建议、仍待用户选择的因素。这个结构便于区分事实、推断与偏好。

## 闭卷检查

1. 一个看起来非常真实的景区3D模型，为什么仍可能无法导航？
2. 相机A能看见两个入口，数据库关系应该怎么表达？
3. 为什么“距离最近”和“当前最快到达”需要不同数据？
4. 为什么有了点云或3DGS，仍可能需要BIM对象表与观察记录？

<details>
<summary>答案要点与纠错</summary>

1. 可能没有可通行道路拓扑、入口语义、尺度标定或碰撞结构；外观只覆盖一类能力。
2. 通过有明确语义的观察关系关联多个实体，并记录关系的有效性与覆盖条件；不能把相机与实体强制一对一。
3. 最近距离只用空间坐标，最快路线还依赖网络拓扑、入口开放、代价和可能的实时状态。
4. 几何采样或视图重建不能自动给出工程对象身份、属性关系和带时间的状态；这些信息需要另行建立并核查关联。

</details>
