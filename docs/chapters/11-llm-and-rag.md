# 11 大语言模型与RAG：参数、上下文和外部证据

图解问的是“东门现在怎样”：旧设计说明的相似度为 **0.98**，当前观察记录只有 **0.91**。为什么不能直接选分数最高的？因为“文字相关”还没有回答“是不是这个东门、是不是现在、是否允许读取”。本章一边沿着这两份材料解释检索，一边拆开模型处理文字的过程。

## 核心判断

语言模型用学到的参数处理上下文并生成输出；检索系统提供可追溯的外部材料。把两者接起来以后，仍须检查检索是否找对、证据是否有效、回答是否忠于证据。

先修：[向量、概率与训练](10-math-and-ml.md)、[数据库](07-databases.md)。

## 从输入文字到输出文字

模型不能直接对纸上的汉字做乘加，需要先把文字变成数。**分词器（tokenizer）** 按自己的编码规则把文字转换成一串编号；每个编号对应一个 **token（模型处理文字的编码单位）**，可能是词、词的一部分或字符、字节片段，因此中文字符数、英文单词数与token数并不相等。

每个编号再查成一组数，也就是上一章的 **向量表示**。Transformer要解决的问题是：处理当前位置时，该从哪些位置取多少信息？它用 **注意力（attention）** 计算这些权重，再组合信息；“注意”在这里是计算规则，不代表人类意识。

### Q、K、V：查什么，凭什么匹配，取回什么

想象你在档案室写报告：先列“我现在需要什么”，再看各袋标签，最后从相关档案里取内容。这个类比只用来记住三种角色：

| 名称 | 档案室直觉 | 自注意力里的准确含义 |
|---|---|---|
| Q：Query，查询向量 | 手里的问题清单 | 当前位置用来与其他位置匹配的一组数 |
| K：Key，键向量 | 档案袋外的索引标签 | 各位置用于被匹配的一组数 |
| V：Value，值向量 | 真正取来汇总的内容 | 各位置提供、按权重相加的一组数 |

在**自注意力**中，Q、K、V都由同一段序列的表示经过不同的、学到的变换产生。一个位置的Q与允许看到的各个K打分，分数经过缩放，再用 **softmax（把分数转为总和为1的非负权重的函数）** 得到权重，最后对V加权求和。[Transformer原论文第3.2节](https://arxiv.org/html/1706.03762v7)

只看“加权汇总”这一步：假设两个V分别是 `[2, 0]`、`[0, 4]`，教学用权重为0.8、0.2，那么结果是 `0.8 × [2, 0] + 0.2 × [0, 4] = [1.6, 0.8]`。这些数是人工设定，用于看清运算；权重0.8不是“这份资料有80%概率正确”。

**类比边界：Q不是用户问题原文，K不是人工标签，V也不是整份文档。** 它们是模型内部的数值表示；自注意力不会凭空访问外部档案室。图解上方的RAG先检索文档，再把材料交给模型，和模型内部的注意力运算属于不同环节。外部资料是否新鲜、真实、可访问，仍须由检索与应用检查。

注意力汇总后，**前馈网络**进一步变换每个位置的数值表示；**位置信息**让模型能区分文字顺序。这里先认识各部分分工，不要求记住整套矩阵维度。

### 为什么通常要接着前面的文字继续生成

如果要练习“根据前文猜下一段文字”，训练时就不能把答案提前露出来。**因果掩码**像遮住后文的纸条，限制某个位置只能利用允许看到的前文与当前位置；即使训练程序拿到了整段样本，也要遵守这个约束。

**自回归生成**指每轮利用输入和已经生成的内容，继续预测下一个token。训练时可在因果约束下并行计算许多位置的预测误差；实际逐步生成时，后面的输入依赖前面已经选出的结果。不能从“Transformer可并行训练”推出“任意长输出都一次生成完”。这里讲常见文本生成方式，其他生成结构与加速方法另有设计。

### KV Cache：把已经算过的标签和内容放手边

每生成一个新token都重算全部前文的K和V，会重复劳动。**KV Cache（键值缓存）** 保存各层已经算过的K、V，后续生成时追加新位置的K、V，并让新位置的Q继续与可用的K匹配。因果注意力中，后续token不会反过来改变这些先前位置的计算，因此可以复用。[Hugging Face 官方缓存说明](https://huggingface.co/docs/transformers/main/cache_explanation)

档案室类比中，这像把刚整理好的标签卡和摘要暂放桌边。边界是：缓存保存的是向量，不是原始档案；它占运行时内存，有适用的模型和上下文条件，也不等于跨任务永久记忆或检索数据库。使用缓存减少重复计算，仍需要处理新输入并计算新的注意力结果。

## 最容易混淆的六种变化

| 动作 | 改了什么 | 一般没有直接改什么 |
|---|---|---|
| 预训练 | 在大量数据上调整模型参数 | 没有自动对齐每个应用规则 |
| 指令微调／SFT | 用示例调整参数与任务行为 | 不保证所有指令都执行正确 |
| 偏好优化／RLHF等 | 利用偏好或奖励改进特定行为 | 不保证事实正确或能力无限提升 |
| Prompt／提示 | 当前调用的输入上下文 | 通常不改模型权重 |
| RAG | 当前调用可用的检索材料 | 通常不改模型权重 |
| 外部记忆 | 可在以后检索的记录 | 不等于模型自然记住全部内容 |

以上是入门区分；具体训练系统会组合这些过程。模型权重、对话上下文、KV cache、数据库记录和人的长期记忆，不是同一种“记忆”。

不能把“缓存还在”“资料已入库”“模型参数已改变”当成同一件事。本章不提供某个引擎或模型的显存公式承诺。

## RAG应当逐段验收

一种常用实现是：文档解析→切分并保留出处→建立关键词或向量索引→按问题召回→权限、时间和主题过滤→必要时重排→把材料交给模型生成带出处的回答。

原始RAG论文研究了参数记忆与可检索的外部记忆组合；今日工程中的各种“先检索再回答”系统不完全等同于论文中的具体训练方案。[Lewis等，2020，摘要与书目](https://arxiv.org/abs/2005.11401)

把知识库比作图纸资料室，把模型比作负责解释资料的人：目录找错、资料过期、解释越过图纸，都可能导致错误。类比边界是模型并非可靠的专业责任主体，流畅说明不能替代来源和验证。

| 故障发生在哪 | 具体例子 | 优先检查 |
|---|---|---|
| 解析 | 表格列关系被拆散 | 抽取内容是否保留结构 |
| 召回 | 搜“相机掉线”只找到网络教材 | 检索词、同义词、索引范围 |
| 过滤 | 旧版本文档排名很高 | 时间、适用项目、权限、版本 |
| 生成 | 把“可能”改成“确定” | 回答与原证据逐条对应 |
| 运行 | 无材料仍输出肯定结论 | 明确未知与补证据路径 |

对已有明确实体ID、坐标、时间的查询，优先使用结构化条件；语义检索用于找相关材料。不要让“名字语义很像”替代身份判断，也不要把“附近”交给文字相似度决定。

## 最小演算：相似度只是一个数值规则

两组数的方向越接近，我们就暂时把它们判得越“相似”。**余弦相似度**用点积衡量方向重合，再除以两组向量各自的长度，避免仅仅因为数字整体更大就得高分。下面query指向第一坐标轴，`near`也主要沿这个方向；先预测它和`other`谁会胜出。

这些向量为人工构造，只展示计算规则，不是预训练 **embedding（把内容映射成向量的表示）**，也不是真实检索质量实验。零向量没有方向；本教学函数约定遇到它返回0。

```python
from math import sqrt

def cosine(a, b):
    # 两个向量各自长度的乘积，用来消除整体大小的影响。
    denom = sqrt(sum(x*x for x in a) * sum(y*y for y in b))
    # 对应位置相乘再相加是点积；本例为零向量约定返回 0。
    return sum(x*y for x, y in zip(a, b)) / denom if denom else 0.0

query = [1.0, 0.0]
docs = {'near': [0.9, 0.1], 'other': [0.1, 0.9]}
print(max(docs, key=lambda name: cosine(query, docs[name])))
```

预期：`near`。但如果near对应一份过期文档，或者它只谈“东门设计”而非“东门当前状态”，相似度再高也不能支持实时结论。

## 如何评价一个知识问答系统

分别检查：相关证据能否进入候选、引用是否支持对应断言、答案是否覆盖问题、证据不足时是否承认、延迟和成本是否可接受。测试集要包含容易混淆的名称、旧版本、没有答案和相互冲突的材料。

模型升级后还需复测这些行为。一次展示成功不能代表所有问题都可靠。学习资料中的版本与历史知识可以稳定保存；最新软件参数、价格和实时状态需要查询当时权威来源。

## 闭卷检查

1. 把新文档上传GitHub，模型参数会自动改变吗？
2. 检索到了包含同一关键词的文档，是否就能回答用户的问题？
3. 一个没有新照片的实体，为什么不能靠LLM“合理猜测”输出当前拥挤程度？
4. 自注意力的Q/K/V、KV Cache与RAG资料库，分别存什么或计算什么？

<details>
<summary>答案要点与纠错</summary>

1. 不会自动改变。需要在问答时读取或检索到文档；是否有连接与权限要实际确认。
2. 要检查材料是否谈同一对象、适用同一时间和版本，是否支持所问断言。
3. 缺少当前证据。模型可能知道一般规律，但这与已观测事实不同；应报告未知及证据时间。
4. Q/K/V是模型内部用于匹配和汇总的向量；KV Cache复用部分已计算的K、V；RAG资料库保存可检索的外部材料。三者都不能自动证明资料真实或获准访问。

通过标准：能分开说清“模型会做什么”“这次给了什么材料”“哪些结论仍无证据”。
