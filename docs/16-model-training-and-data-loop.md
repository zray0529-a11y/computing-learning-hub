# 行业模型研发与数据进化闭环：从1 TB数据到可验证的能力

想象一个虚构展览园区：摄像头看到东门人多，AI查地图和客流，提出引导建议，工作人员审批后执行。二十分钟后，系统收集结果。这样就算AI学会了吗？**不一定。记录经验、读取经验、利用经验更新模型，是三件不同的事。**

学习目标：能分清数据量、模型大小、每次计算量；知道何时应该改知识库、工作流或模型权重；能设计一条有数据质量控制和验收的学习闭环。

先修：[机器学习](chapters/10-math-and-ml.md)、[LLM与RAG](chapters/11-llm-and-rag.md)、[Agent](chapters/12-agents.md)。应用衔接：[数字孪生](chapters/14-spatial-systems.md)、[安全与可靠性](chapters/13-security-and-reliability.md)。

## 1. 1T到底有多大：三把不同的尺子

| 写法 | 量的是什么 | 教学例 |
|---|---|---|
| 1 TB（十进制） | 10^12 字节，文件容量 | 1,000 GB；1 TiB则为2^40字节 |
| 1T tokens | 10^12 个分词或模型编码单位 | 训练处理了多少token；重复轮次也可能计入 |
| 1T parameters | 10^12 个模型参数 | 存放这些数所需字节与精度有关 |

假设1 TB全是未压缩纯文本，平均每token占4字节，则约250B tokens（2,500亿）；如果平均2.5至5字节，则是200B至400B。它只是条件估算，必须实际运行目标分词器。UTF-8常见汉字占3字节；汉字数并不等于token数。

若1 TB全是平均2 Mbps的编码视频，不计容器额外开销，约1,111小时；并不能把这些字节直接换算成视觉token。还需知道采样帧率、分辨率、编码器、切片和重复程度。连续一千帧几乎相同，不等于一千个独立事件。

**量级练习**：10万条案例，每条2,000 tokens，共200M tokens；按4字节估算约800 MB（0.8 GB），训练3轮会处理约600M tokens，不会凭空多出两倍独立经验。1 TB可能是约1.25亿条这样的案例，也可能主要是重复画面，不能据容量判断有效训练量。训练成本还取决于模型、序列长度、批量、精度、硬件、训练方式和RL生成轨迹等，不存在通用的“1 TB要多少GPU”答案。

## 2. 新模型怎样看：总参数、激活参数和训练量

可以想象一所大医院：有许多科室，病人不需要每次看遍所有医生。**MoE（混合专家）** 模型通过内部路由，通常在每个MoE层、每个token上选择一部分前馈网络专家，再汇合它们的输出。其他共享计算仍然存在。专家是内部神经网络模块，不一定对应人能命名的行业，不等于一群各自完整的1B语言模型。

下面是2026-11-26读取官方模型卡得到的版本快照，不是永久排名：

| 官方模型 | 参数规模（厂商口径） | 路由与训练信息 |
|---|---|---|
| DeepSeek-V4.1-Flash | 主干552B，另有约196B Engram条件记忆；输入预填充每token激活8B、输出生成每token激活16B（主干口径） | 每MoE层384个可路由专家、选6个，加1个共享专家；预训练45T多模态tokens |
| Kimi K3.1 Pro | 总量约2.8T，每token激活104B | 896个专家、选16个，加2个共享专家；从K3进行跨领域联合RL后训练，也更新了部分注意力结构；训练token总量未在本次已读模型卡中核实 |

来源：[DeepSeek官方模型卡](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/main/README.md)（架构、预训练、后训练）；[Moonshot官方模型卡](https://huggingface.co/moonshotai/Kimi-K3.1-Pro/blob/main/README.md)（介绍、模型规格、架构变化）。均为厂商披露，未下载权重、复现评测或独立测量。

不要把DeepSeek的主干参数与Kimi的总参数当作完全同口径；Engram是学习到的条件查表记忆模块，不是外部实时数据库。Kimi的104B约占2.8T的3.7%，并不表示部署只需存放104B。仅以2.8T参数全按4 bit存放的理想数学估算就是1.4 TB，尚未计量化元数据、较高精度的部分权重、KV缓存、运行时与通信开销；这不是具体部署显存承诺。训练还要考虑梯度、优化器状态和激活。

也不要用激活比例直接比较速度或能力。注意力、路由、硬件与实现会影响结果。45T是多模态训练token，不是45 TB；1T token在算术上是45T的约2.22%，不表示等比例的知识、成本或模型效果。模型卡公开权重不等于所有训练数据、代码或许可均开放；实际使用前查具体许可证和运行框架。

## 3. 让模型变专业，有三条独立的轴

把AI想象成一个读过通识课的学生。下面的比喻用来记住目标，而不是说模型像人一样理解或形成可准确查回的记忆。

**轴一：学什么、用什么目标训练？**

| 方法 | 比喻 | 输入和实际变化 |
|---|---|---|
| 继续预训练 CPT（领域自适应） | 补专业课 | 用领域语料继续优化预训练目标，通常是预测token；可能增强领域表示，也可能遗忘通用能力 |
| 监督微调 SFT | 看标准例题 | 输入及目标输出、可观察工具调用等示例；优化目标答案的生成概率 |
| DPO 直接偏好优化 | 老师比较两份作业 | 同一输入下较优与较差的答案，直接优化偏好目标；不必像典型在线RL一样在微调过程中不断采样 |
| 强化学习 RL | 做题、按规则评分 | 根据任务、动作轨迹、奖励或验证器优化策略；可用仿真但仿真非必需 |
| 蒸馏／OPD | 向老师学习 | 用教师输出或概率等监督学生；在线策略蒸馏通常让学生采样、利用教师信号改进，具体算法各异 |

后训练是预训练之后塑造行为和能力的阶段，可包含SFT、偏好优化、RL、蒸馏等；不同团队的阶段命名并非完全统一。微调是从已有模型继续训练的做法，和后训练不是互斥分类。DeepSeek的模型卡披露SFT、RL及OPD，并强调任务与环境合成管线；Kimi披露多领域联合RL。这些说明了训练任务与可验证反馈的价值，但不说明RL能凭空得到可靠的现实决策能力。

**轴二：训练哪些数？**

- 全参数微调：通常允许全部模型权重更新，不表示每步每个权重必然改变。
- LoRA：冻结原权重，在指定线性层加入可训练的低秩变化。可用SFT等训练目标；参数减少不等于计算成本同比例减少，仍需通过基础模型计算。QLoRA进一步用量化基础权重等技术减少内存占用。
- ESFT：针对MoE，识别任务相关的内部专家并选择性训练。它不同于LoRA，二者可在适合的实现中组合。
- 学习率、批量、轮数等是训练超参数；temperature、top-p、reasoning effort等是推理配置，通常不更新权重。调整推理预算也可能提高任务表现，但不是训练。

**轴三：是否必须训练？** 新规范、新天气、库存和当前拥堵应当由数据库、RAG和工具按需读取；操作规则还可由Prompt、Skills、工作流与权限控制表达。只有评测表明稳定且重复出现的能力短板值得内化时，才考虑训练。行业微调并不保证事实准确或合规。API只能使用服务商公开支持的功能，不能假定可以修改内部权重。

## 4. 多个1B模型与一个大模型，有六种不同的合作方式

| 技术方向 | 实际发生什么 | 主要目标与边界 |
|---|---|---|
| 模型路由／级联 | 外部程序、分类器或小模型决定独立调用哪个模型，或先小后大、失败升级 | 省调用成本；错误分流也会损害质量 |
| 专项小模型与Agent工具 | 识别、分类、提取、预测等独立服务把结构化结果交给Agent | 让大量重复任务便宜可靠；1B不是必需规模，视觉任务需要合适的视觉模型 |
| MoE内部路由 | 在一个模型内部逐层逐token选择专家模块 | 稀疏计算；不等于一个小模型通过API唤醒指定的大模型参数 |
| ESFT专家定向微调 | 测量相关专家的使用等信息，再训练选择的模块 | 领域适配研究路线；需要权重、训练框架和专项验证 |
| 多LoRA适配器 | 同一个基座按任务加载匹配的低秩参数；亦可研究动态组合 | 共享基座、维护多种能力；适配器不能任意混搭，组合须评测 |
| 投机解码 | 草稿模型或草稿头快速提出候选token，目标模型验证并接受或修正 | 主要用于加速解码，不是判断现实事实是否正确；精确算法可保持目标采样分布 |

一句话区分：路由是选择找谁做；MoE是同一个模型内部哪些模块参与运算；LoRA/ESFT是学习时改哪些数；投机解码是怎样更快生成。小模型接大模型的输出叫协作或级联，不自动构成模型内部的参数激活。即使几种技术能够一起使用，也要分别验收。

证据与成熟度：外部路由有[RouteLLM](https://arxiv.org/abs/2406.18665)研究，专家定向训练有[DeepSeek ESFT](https://github.com/deepseek-ai/ESFT)研究与代码，多适配器部署有[S-LoRA](https://arxiv.org/abs/2311.03285)研究，投机解码的经典原理见[Leviathan等](https://arxiv.org/abs/2211.17192)。不能将这些论文实验直接外推到任意万亿参数模型。基础模型变更后，适配器与路由器可能需要重新训练或校准。

## 5. 两个闭环：让系统工作，与让模型学习

以下是教学架构而非某厂商内部实现。以虚构园区东门拥堵为例，先把线上和离线分开：

| 线上业务循环（现在发生） | 离线学习循环（经过验收的迭代） |
|---|---|
| 传感器、图片、业务记录 → 实体、时间、状态和证据 | 运行记录 → 筛选、去重、脱敏、标注与审核 |
| 小模型或规则识别 → 需要时升级给大模型和工具 | 诊断错误来源 → 决定改数据、Prompt、工具、路由还是权重 |
| Agent读取当前证据 → 提出建议 → 人工或规则授权 → 执行 | 形成版本化数据集和独立评测集 → 小规模训练或系统修订 |
| 核实执行结果 → 更新外部状态 → 继续服务 | 比较基线 → 安全门禁 → 影子测试（只观测不执行）与受控发布 → 监测、必要时回滚 |

线上采集持续发生，不意味着实时自动更新模型权重。学习闭环可以有多个迭代速度：状态按业务时效刷新；知识和工作流按审查发布；模型仅在有足够证据时训练、验证、发布。训练与发布分别受控。

### 数据沉淀：不要把所有东西扔进一个训练库

| 数据资产 | 保存什么 | 去哪里 |
|---|---|---|
| 原始证据 | 合法采集的画面、设备记录、来源与采集时间 | 权限控制的原始存储，设置保存期限 |
| 可查询的世界状态 | 对象ID、坐标、观测、时间、可信度及证据索引 | GIS、实体数据库、时序数据、文档检索 |
| 任务和执行轨迹 | 问题、模型和工具版本、可观察动作、输入输出、失败与审批 | 运行日志、案例库；不需要采集模型私有思维链 |
| 专家教学样本 | 审核后的标准处理、反例、偏好对、可验证任务 | 版本化训练候选集；分别适配SFT、DPO、RL等 |
| 评测与结果 | 独立任务、正确或允许的结果、评分规则、真实结果与影响因素 | 独立测试、监控和反馈库；不拿测试答案训练 |

关键不是把数据分成绝对价值等级。原始证据对追溯有价值，真实反馈也可能有噪声或偏差。数据管线需要访问权限、授权范围、保留期、隐私保护、来源、标注规则、审核记录、版本、质量和删除/撤回能力。未经审核的模型输出不是事实标签。若记录可能含个人信息，应尽量少采集，并确认授权及后续训练用途。

### 一个案例至少需要什么？

下面是假设的教学样本，不是实际园区资料。先看记录是否足以支持任何因果结论。

| 字段组 | 虚构内容 |
|---|---|
| 身份与证据 | case-demo-001；east-gate；观察时间10:00；计数证据obs-001；状态拥挤 |
| 决策前信息 | 东门计数100；西门30；天气未知；通行能力待核验 |
| 建议与审批 | 查询通行能力后再建议引导，需工作人员批准；未经审批不改变入口 |
| 实际执行 | 审批后执行指定引导，记录动作和实际时间 |
| 结果与干扰 | 10:20东门计数降为70；同期降雨、到达流量等情况未核实 |
| 复核及版本 | 专家标注为“结果改善，因果未确定”；原始证据、标注、模型、规则及数据集版本可追溯 |

可以制作不同学习材料：SFT教“缺证据先查”，DPO比较“直接封门”和“先核验并走审批”的建议，RL任务定义允许动作、奖励和安全约束。不要把“东门从100变70”直接当成引导措施产生30%效果的因果证据。天气、客流变化和其他措施可能同时起作用；需要合理的对照、实验设计、领域知识或因果分析。

## 6. 数据如何迭代：考试卷和教材分开放

一个可执行的最小流程建议：

1. 先定义任务与指标：拥堵识别的漏报/误报、证据正确率、拒绝越权、延迟、成本，分别设目标和失败条件。
2. 建立原模型和简单规则的基线。优先修时间、实体匹配、检索、工具契约等系统错误，而非把每个错误都归因于模型。
3. 收集失败及成功案例，优先覆盖边界情况、难例、不同时间和空间；保留真实分布，避免只留成功。
4. 按事件、地点、时间或相近数据组隔离训练、验证、测试，避免同一视频的相邻帧落入不同集合。冻结评测版本；不能反复看测试答案调参。
5. 用小样本比较规则、RAG、不同模型与LoRA等。记录数据集版本、基座与适配器、训练配置、评测版本、运行依赖和结果；同时复测通用能力与安全边界。
6. 达标后小范围受控发布；观察漂移、异常、业务结果与成本。低于门槛就回滚，新的反馈进入候选数据池，不直接成为监督真值。

没有适用于所有行业的样本数门槛。数百或数千条人工审核的任务样本可以作为小规模试验设计，不能保证效果。通过增量数据的学习曲线与误差类型判断继续采集是否有收益；在相同评测和成本口径下比较不同方案。部署前也要核对开放权重许可、数据许可与基础设施是否支持训练。

### 仿真不等于三维展示

三维园区可以让人看见布局，却不一定能让AI学习“改变入口之后客流会怎样”。可训练环境需要状态、合法动作、状态转移、终止条件、评分规则，以及可重复重置的场景。真实记录用于校准仿真，模拟结果与现实结果分别标记来源，检验仿真和现实的差异。

例如做一个简单排队模型，把入口通行能力、到达率与排队长度作为状态；先验证它能否复现历史观测，再允许Agent在虚拟环境里提出策略并评分。安全约束和审批是硬边界，不能用提升客流或收入的奖励抵消。模型可能钻评分漏洞；要保留独立验证、压力测试与人工复核。不在真实人群中让未经验证的策略自由探索。

## 7. 研发投入顺序：先做小试验

| 步骤（建议，不是行业统一标准） | 实验 | 达标后才推进 |
|---|---|---|
| P0 | 通用模型 + 只读工具、证据检索、规则 | 可以重复完成任务，知道错误出在哪 |
| P1 | 建立独立评测；小模型分类或路由 | 在相同质量门槛下验证成本/延迟改善 |
| P2 | 小模型SFT/LoRA；教师生成经审核的样本 | 专项能力提升，不牺牲关键安全及通用能力 |
| P3 | 领域CPT、ESFT、多适配器实验 | 明确额外训练收益、算力成本与维护代价 |
| P4 | 可重置的任务环境、偏好优化或RL | 验证评分可信、策略可迁移，失败可恢复 |

并非每个阶段都必须做。行业公司不需要从头训练巨型模型才能建立壁垒；可追溯的领域数据、执行反馈、评测体系和可靠工具可能更重要。新的数据量或模型大小不是最终验收指标。

## 8. 费曼式自测：不背名词，先预测

1. 1 TB重复视频与1 TB独立专家案例，能否直接说训练价值一样？
2. 外部1B模型判断要调用Kimi，它是否选择了Kimi某一层的内部专家？若想学习专家路由，该查哪一层？
3. 明天的展馆开放时间变更，应先做RAG/数据库更新还是重新微调？
4. 一条疏导建议实施后人少了，能否自动记成RL正奖励并上线新版模型？
5. 如果同一段视频的相邻帧既进入训练又进入测试，会怎样？

5. 数据泄漏会让测试看起来比真实泛化更好；按事件或序列分组隔离，而不是仅随机分帧。
